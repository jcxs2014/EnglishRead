## 零、审查前先说清楚的一件事：门禁对哪一类缺陷是瞎的

a 步 13 项门禁全绿时，本书有 **62 处「第 X 章」中文式跨章指向、160 个引语块的说话人归属、20 章的事实陈述** 全部未经验证，而其中**有 60 多处是错的**。

原因不是门禁坏了，是口径不匹配：

| 门禁 | 它检查什么 | 它看不见什么 |
|---|---|---|
| `verify_quotes` / `sweep_full` | 引语是否**逐字**在 `text/` 里 | 这句引语**是谁说的**、前后文是不是这个意思 |
| `check_chapter_quotes` | 引语属不属于标注的那一章 | 章节内的人物、动作、性别、数字对不对 |
| `check_xref_indep` | `chNN` + 紧跟英文引语 的指针 | **中文形态「第 X 章」**——本书 62 处全部漏掉 |
| `audit_structure` | 每个块有没有四个子项 | 子项**内容**对不对（子项检查是假阴性高发点） |
| `check_nav_layer` / `sweep_analysis_inline` | 导航层与行内**英文**是否逐字 | 导航层与行内的**中文事实断言** |

结论（写进本报告，也写进 `.memory/AGENTS.md` 的教训）：**缺陷率由生产方式决定，不由检查条数决定。**
这次真正抓出东西的动作只有一个——**把 md 里每个 `chNN` / 「第 N 章」＋紧随短语抽出来，逐条回 `text/chNN` 查**，
而这条动作在 13 项门禁里没有任何一项在做。

## 五、这次审查沉淀下来的三条规矩

1. **「跨章指向逐条 grep 核实」从临时动作升为常设清单项。** 判据只依赖动作、不依赖脚本：写出任何「第 X 章……」或「某人做了什么」之前，先 grep 被引章节找那句话，找不到就删或改挂。
2. **批量改 md 前必须 dry-run 验证每条命中恰好 1 次。** 我自己踩过：`p = f if f in files else files.setdefault(...)` 写错后第二次起 `p` 变成文件名字符串，导致每文件只有第一条替换成功——20 处里 17 处静默没改。**空输出/低命中数不是「没问题」，是脚本坏了。**
3. **要写「某件事不存在」之前，grep 必须在整个文件上跑一遍，并且先看目标 md 里有没有别处已经写着它。** 本次最重的一次自伤就出在这里——我凭半章的印象断言「ch09 无火灾」，而同一个 md 里有三处写着那场火；把一处改掉、留下三处，等于自己造出自相矛盾。**md 内部互相打架，是「上一批改错了」最可靠的信号。**
