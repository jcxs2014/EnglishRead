## R2-8 · 解析盲区：块在「本章导航」段里，全书解析 0 块却报「块数 0」（阻断型，2026-10-24 下午复验新增）

> 本项不在原 R2 清单内。复核方在复验 R2-1 修复时，拿 15 本清单里的 `bruja-s-nest` 再跑一遍才发现：
> 它**仍然 EXIT=1**，但红的原因不是 15 上限，而是全章报「块数 0 低于下限 2」。

### 症状

```
=== ⑳ 整书体检 ===
  ❌ ch01：块数 0 低于下限 2（新书（基线 0 章 <3，按 2–15 硬门））
  ❌ ch02：块数 0 低于下限 2（新书（基线 0 章 <3，按 2–15 硬门））
```

而 `ch05` 实有 **14 个 `> **原句 N:**` 块**。

### 根因（比「缺 `## 精读` 节」深一层）

`parse_md` 有两道闸，任一道都足以零命中：

| 闸 | 旧代码 | 后果 |
|---|---|---|
| ① 正文判定 | `in_body = "精读" in ln` | 这批书没有「精读」节 ⇒ 永远 False |
| ② 导航段跳过 | `if in_nav: … continue` | 即使放行 ①，**块排在 `## 本章导航` 段内**，仍被整段跳过 |

只修 ① 不够——实测修完 `bruja` ch05 仍报 0 块。**这几本书的结构是：导航标题之后直接排块，没有独立精读节。**

连带同源 bug：`---` 不复位 `in_nav`，而 `NAV_RE` 的列表符可选 ⇒ 每个块头 `**原句 N：**` 都被数成导航项。
`bruja` ch05 报「导航 **60** 项」，正好 4 + 14×4。

### 为什么长期没人发现

- 解析器**不抛异常**，只是零命中；空集上的「块数 0」「子项缺」「中文过薄」全都算得出来、报得像真结论。
- 与本期另一处事故同型：`book_block_stats()` 误写 `parse_chapter`（应为 `parse_md`），异常被 `except` 吞掉
  ⇒ 基线恒 0 ⇒ 所有书静默退回硬门。**一个是「抛异常被吞」，一个是「不抛异常但零命中」，一样静默。**

### 处置（已修，`a47ce38a2`）

1. **正文判定**：全文先扫有没有 `## …精读…` 节；没有就不靠标题切正文，块一律按顶层处理。
