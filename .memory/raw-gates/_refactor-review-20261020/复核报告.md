### B-1 · 回归测试集 81 条里有 10 条是空跑（工具行为零覆盖，且报绿）

**文件**：`scripts/tests/cases.json`（10 条 id）

**现象**：这 10 条的 `cmd` 指向 `scripts/audit_structure.py` / `scripts/check_quote_order.py`——这两个文件在本次重构里被搬进了 `scripts/structurecheck/`。基线里录的是**命令根本启动不了**的报错：

```json
{
 "id": "fabulous-bodies-by-chuck-tingle:structure",
 "cmd": ["python3", "scripts/audit_structure.py", "notes/books/novels/fabulous-bodies-by-chuck-tingle", "--quiet"],
 "head": "fb8918c5b425",
 "rc": 2,
 "sha": "1e855d891486316c",
 "tail": ["/opt/homebrew/Cellar/python@3.15/.../Python: can't open file '/Users/jcxs2014/Documents/Works/EnglishRead/scripts/audit_structure.py': [Errno 2] No such file or directory"]
}
```

runner 的判定是 `same = rc == c["rc"] and rec["sha"] == c["sha"]`（`scripts/tests/run_cases.py:87`）——rc 仍是 2、输出仍是同一句报错 ⇒ sha 也一样 ⇒ 报 ✅。

```bash
$ python3 - <<'PY'
import json, pathlib
c=json.load(open('scripts/tests/cases.json'))
stale=[x['id'] for x in c if x['cmd'][1].endswith('.py') and not pathlib.Path(x['cmd'][1]).exists()]
print(len(stale)); [print(' ',i) for i in stale]
PY
10
  fabulous-bodies-by-chuck-tingle:structure
  fabulous-bodies-by-chuck-tingle:order
  finding-darla-by-vidhya-sathyamoorthy:structure
  finding-darla-by-vidhya-sathyamoorthy:order
  the-dues-don-ts-of-magic-by-delemhach:structure
  the-dues-don-ts-of-magic-by-delemhach:order
  capture-by-amanda-lohrey:structure
  capture-by-amanda-lohrey:order
  wings-of-starlight-by-allison-saft:structure
  wings-of-starlight-by-allison-saft:order
```

**为什么是缺陷**：回归集的作用是「合并/改口径后必须一字不差」。这 10 条锁住的不是判定，是「这个文件不在了」——**它对 `audit_structure` / `check_quote_order` 的行为零覆盖**，却贡献了 12% 的「绿灯」。这正是 §E 要求排查的"工具误报被录成基线"。而且它**会自我掩盖**：以后谁把 `structurecheck/audit.py` 的判据改坏了，这 10 条照样绿。

**为什么现在没出事（部分缓解）**：`structure-audit` / `structure-order` 的**新路径**版本（`scripts/structure.py`）是另外录的、在跑的、也真的匹配：

```bash
$ python3 scripts/tests/run_cases.py | grep structure
✅ fabulous-bodies-by-chuck-tingle:structure-audit
✅ fabulous-bodies-by-chuck-tingle:structure-order
✅ finding-darla-by-vidhya-sathyamoorthy:structure-order
```

⇒ 覆盖没丢，但**旧那 10 条是纯冗余 + 假绿**，且一旦有人按 `cmd` 字段去手跑这 10 条，会拿到一个看不懂的报错。

**阴性对照（证明"✅"在这 10 条上确实没意义）**：

```bash
# 把一条「活」case 的 cmd 指向不存在的脚本，再按 runner 的逻辑重录基线
$ python3 - <<'PY'
import json,subprocess,pathlib,hashlib
c=json.load(open('scripts/tests/cases.json'))
for x in c:
    if x['id']=='fabulous-bodies-by-chuck-tingle:structure-audit':
        x['cmd']=['python3','scripts/audit_structure.py', x['book'],'--quiet']
        r=subprocess.run(x['cmd'],capture_output=True,text=True)
        out=r.stdout+r.stderr
        x['rc']=r.returncode; x['sha']=hashlib.sha256(out.encode()).hexdigest()[:16]
json.dump(c,open('/tmp/rt/cases.json','w'),ensure_ascii=False,indent=1)
PY
重录后的 rc = 2
重录后的 tail = /opt/homebrew/Cellar/python@3.15/.../Python: can't open file '.../scripts/audit_structure.py'
$ python3 /tmp/rt/run_cases.py -k fabulous-bodies-by-chuck-tingle:structure-audit
✅ fabulous-bodies-by-chuck-tingle:structure-audit
合计 1 条：一致 1，不一致 0，跳过 0
EXIT=0
```

⇒ **命令跑不起来 → 录基线 → 报绿**，这条路径是通的。（对照组：篡改一条**活** case 的 sha，runner 立刻报 `不一致 1` + `EXIT=1`，说明 ✅ 在活 case 上是有意义的。）

**建议改法**：
1. `scripts/tests/run_cases.py` 增加一条**前置硬判据**——命令若 `rc==2` 且 stderr 含 `can't open file` / `No such file or directory`，**直接判 ❌ 并拒绝录基线**（现在 `--record` 会照录）。
2. 这 10 条的 `cmd` 改成 `scripts/structure.py audit|order ...`，然后 `--record` 重录。
3. `cases.json` 里删掉已失效的旧 `cmd`（或加 `"legacy": true` 标记，让 runner 跳过而不是绿）。

**现象**：该脚本已被合并进 `scripts/overview.py`，文件不再存在：

（附带：同一条命令也在 §G 的清单里被列为死命令。）

**建议改法**：`docs/新书启动模板.md:184` 改成 `python3 scripts/overview.py quotes "<书目录>" "<epub>"`。
