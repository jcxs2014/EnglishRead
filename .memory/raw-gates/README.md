# `.memory/raw-gates/` — 五步审查的原始门禁输出

**这是什么**：第 10 条 a–e 五步审查（以及完工自审）时，各检测器的**原始逐行输出**落盘处。
AGENTS 第 10 条「完成报告硬要求」要求原始输出**全量留存**；本目录就是那个「全量」的落点，
而 `.memory/daily/YYYY-MM-DD.md` 的对应书条目里放**摘要表 + 指向本目录的一行**。

**为什么不在 daily 日志里全量贴**：13 个检测器的逐行输出单次可达数百 KB（实测 Paris Deception
17 个文件 191 KB），塞进当日日志会让那一天的日志不可读，且 `post_collab.py daily` 的长度门禁
会直接拒收追加。**分工：日志放摘要与定性，raw-gates 放可核的原件。**

## 目录约定（`raw-gates/<书目录 slug>/<YYYY-MM-DD>-<步骤>.txt`）

- **一级目录 = 书的目录 slug**（与 `notes/books/` 下同名，去掉 `-by-作者`）——
  后来者**不必 grep 就能猜到路径**，这正是旧命名 `review-raw-2026-09-29-pd/` 的毛病：
  它把书名编码成只有当时那台机器知道的口号（`pd`／`ihsqfy`），日期又进了目录名，
  同一本书跨天审就要多一个目录。
- **文件名 = 审查日期 + 步骤**。步骤名沿用第 10 条的 a/b/c/d/e，可再加序号
  （`a1`、`a2`、`c2`…）表示同一步的多次运行。`a_review_gates_full` = a 步 13 个检测器一次跑完；
  `final_gates_after_all_fixes` = 整改后终态复跑。

## 引用写法

在协作板与工作日志里**只写指针**，不要把逐行输出贴进去：

```
**原始输出指引**：a 步 13 个检测器逐行输出见
`.memory/raw-gates/<书目录 slug>/<YYYY-MM-DD>-a_review_gates_full.txt`，
整改后终态见同目录 `<YYYY-MM-DD>-final_gates_after_all_fixes.txt`。
```

指针属**活引用**（指引读者去读），与「在讲一个已修 bug 的故事里提到某个历史路径」不同——
后者是死链，不该被死链检查算成缺陷（AGENTS 验收纪律）。
