## 三、每条要补的四个子项（缺一不可，顺序照下）

现有形态是「编号 + 引语」两行，例如：

```
① "She stands there in the aftermath, trapped behind a wall of glass in a silent, seismic horror."（ch01）
```

改完是：

```
## ①

> "She stands there in the aftermath, trapped behind a wall of glass in a silent, seismic horror."（ch01）

**中文理解**：她站在那一幕的余波里，被一层无声而剧变的恐怖挡在玻璃墙后。

**上下文**：ch01 结尾，爆炸刚过，Lila 隔着一层玻璃看着诊室里的废墟——她人在外面，能看见，进不去。

**为什么重要**：整本书的处境被压缩进一个动词短语——`trapped behind`。玻璃是透明的、看得见的，却正好把她隔在事故之外；这不是"受伤"，是"被排除在后果之外"，正是她后来全部行为的动机。

**呼应关系**：与 ⑭、㉓ 呼应：⑭ 里她第一次承认"我想被看见"，㉓ 里她终于承认自己"其实一直在玻璃外面"。开篇的这道玻璃，结尾才被说破。
```

**四条各自的要求**：

1. **中文理解**：这一句的忠实翻译。人名地名书名保留英文。不解释、不发挥。
2. **上下文**：这句出自哪一章、当时**发生了什么**。必须回该章 `text/` 文件取证（下面第四节）。
3. **为什么重要**：这句在**写法**或**主题**上起了什么作用（用词、节奏、视角、道具、结构位置）。禁止写「本句描写了……」「作者通过……表达了……」这类套话——全库有判据会把它们打成模板句。
4. **呼应关系**：与哪几条呼应（写编号），或与哪一章的情节呼应（写 `chNN`）。**只能指真实存在的编号**；本文件只有 ①–㉚，不许引用不存在的号。实在没有呼应的，写「独立成句，无内部呼应」，不要硬凑。

**格式硬要求**：条目用 `## ①` 起头；引语行改成 `> "…"（chNN）` 引用块；四个子项各自独立成段，`**中文理解**：` 这种粗体标签顶格写。

## 四、取证纪律（这一条最容易翻车）

1. **上下文、人物关系、数字、结局，一律回 `text/chNN_*.txt` 用 grep 找依据**。找不到依据的，改说法或删掉该细节——**不许凭印象写**。
2. grep 零命中时**先怀疑自己的命令**：macOS 的 `grep` 里 `\|` 不生效，要用 `grep -E`。报「原文没有」必须贴命令与输出。
3. 引语本身**逐字不动**（包括弯引号）。若发现引语与原文不符，**不要改引语**，在交付报告里单列出来交我处理。
4. 拿不准的条目：**保留最保守的写法**，并在报告里标出「拿不准：第 N 条，原因是……」。
