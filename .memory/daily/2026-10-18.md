## 【工具盲区】`check_entities` 三处改动 + D1/D3 规则落地（C/D 组收尾，2026-10-18）

承接用户授权「处理其他 C/D 组的问题」。本条记录 `check_entities` 的三处改动、两处投毒抓出的跳过型假绿、D1/D3 规则落地，以及我自己犯的三个错。

### 改动 1：`--wide` 开关（宽口径 + 行级剔元信息，非默认）

**背景**：2026-10-18 上午先堵了「抽 0 段仍 exit 0」的真空绿（同工具第一个形态）。剩下的问题是——非虚构书的梗概层标题是 `概览`(1,722 处) / `论证结构`(1,133 处) / `全书梗概`(313)，全都不在 `syn_pat` 的 4 个标题内 ⇒ 108 本书抽 0 段。文档里写着「扩口径已实测否决」：报错文件 232 → 969，95 本由绿转红，新增全是 `ISBN`/`Liveright Publishing Corporation`/`Norton`/`Borzoi Books`/`Grove Press` 之类出版噪声。

**本轮把噪声剔除做出来，再谈扩口径**。关键决定是**剔行不剔词**：

```
META_LINE = ^\s*[-*]?\s*\**\s*(?:出处|作者|来源|栏目|来源栏目|字数|字符数|篇目|篇目来源
             |原文出处|章节定位|体裁|文本体裁|书籍信息|出版信息|系列)\s*\**\s*[:：/]
```

理由：读行核实后发现，残余项**不是散落在梗概正文里的专名，而是整行的书目元信息**——`- **出处**：*书名：副标题*`、`- **作者**：X（1948– ）`、`- **字符数**：约 23,400`、`- **章节定位**：…（Knopf, 2022）`、`**来源/栏目**：言情小说长篇（Contemporary Romance）`。最大一档是**行内括注形态**，任何词表都会漏它（我第一版就想用词表，实测 `Contemporary Romance` 38 次全漏）。

**量化**（483 本有 `text/` 的书，85 本有新增段，`概览` 节正文 47,637 行）：
- 元信息行 **5,544 行 = 11.6%**；剔掉后新增实体 **1,903 次 → 122 次**：作者/书名 990→3 · 出版信息 177→2 · 分部标签 126→11，涉及 **28 本**书。
- 全库对照（默认 / `--wide` 全文件 / `--wide`+只章级 md）：报错文件 **232 / 378 / —**，报错书 39 / 121 / —，梗概段 14,688 / 18,179 / 16,046。

**为什么不做成默认**：改判定口径（全库报错数会变）＝新增检查项，与 `AGENTS.md` 第 8 条「先问生产方式」同向，须单独授权（同 lane ⑲ 教训）。`--wide` 只做取证，已登记在档案待裁决。

### 改动 2（我撞出的）：语料层不存在 ⇒ 全书实体全报「未知」

`load_corpus()` 在既无 `text/*.txt` 又无 `library/*.epub` 时返回**空串**，于是「实体不在语料里」对**每一个**实体都成立 ⇒ 全报未知。在无真值时判「未知」是不出结论 ⇒ 与「抽 0 段」同口径：`check_book` 返回 `corpus_len`，`main()` 在 `corpus_len == 0` 时先于 `seg_total == 0` 分流，打印「⚠️ 语料层不存在」+「❓ 无法判定」+ 修法指引，`exit 2`。

### 改动 3（投毒抓出，最要紧）：相邻两个梗概层标题 ⇒ 上一节被静默丢弃

在 `--wide` 上做投毒（往 `## 概览` 下插一行含虚构实体 `本章讨论 Zorblatt Quendera 的假说，并提到 Kelvin Wrathbridge 的实验。`），**投毒没被抓到**——但不是「工具漏判」，而是更糟：**那一节根本没进扫描集**。`extract_synopses` 只返回 1 段（`## 论证结构` 的内容），`## 概览` 的 1012 字被丢弃。

根因在循环控制流：

```python
if (syn_pat_wide if wide else syn_pat).match(line.strip()):
    in_syn = True; buf = []; continue        # ← 无条件重置，上一节被丢
if in_syn:
    if head_pat.match(line.strip()):
        out.append((cur_num or '?', ' '.join(buf)))   # ← 只有"非梗概标题的 H2"才 flush
```

遇到第二个梗概层标题时走的是第一条分支，**既不 flush 也不收**。这个缺陷**早于 `--wide`**，只是默认口径下 `故事梗概`/`本章导航` 紧邻罕见；`--wide` 收进 `概览`+`论证结构` 后，「概览后紧跟论证结构」成为全库常态。修法：进新梗概节前先 `if in_syn and buf: out.append(...)`。

**规模**：默认口径全库报错文件 **232 → 234**、梗概段 **14,688 → 14,740（+52）**、未知实体项 276 → 278。用 `git show HEAD:scripts/check_entities.py` 装成模块逐书对照，确认新增/消失分别为 2/0。

**新增的 2 个文件已逐条读行核实**：
- ✅ **真缺陷**：`notes1/books/novels/the-glass-girl-by-kathleen-glasgow/ch07 monday.md` 报 `Patrick`——该名在**全部 55 个 `text/*.txt` 里出现 0 次**，且 `library/` 有 epub（真值可用）⇒ 梗概层出现无文本支撑的人物名。
- ❌ **假红**：同书 `ch05 everyone_is_gone.md` 报 `HTML`，来自 `**叙事手法**：…（与 ch02 同样是源 HTML 的单 <p>）` ⇒ 技术术语。

**教训（已写进 docstring）**：`--wide` 这类「扩大扫描集」的改动**必须配投毒测试**。扩大扫描集最可能的失败形态不是「多报错」，而是**「看似收进来了其实没收到」**——而任何计数都看不出这件事，本轮是靠段数 19→37 + 投毒没被抓到才暴露的。

### ⚠️ 我在算「受影响集」时犯的两个错（取证反面）

**错误 1：基线 commit 取错 —— 用 `git show HEAD:` 算出「0 本受影响」。**
C 组四个工具的修复**已经在 `d1fe13417` 里 commit 了** ⇒ `HEAD` 与工作树是同一份修后代码，
比对必然是「0 本受影响」。真实是 17 本。
**正确基线 = 该工具最后一次改动 commit 的父版本**：
```bash
BASE=$(git log -1 --format=%H -- scripts/<检查器>.py)   # 本轮 = d1fe13417
git rev-parse $BASE^                                    # 313a7c487
git show 313a7c487:scripts/<检查器>.py > /tmp/old.py     # 落成临时脚本
```
⚠️ 这一条已经写进 `AGENTS.md` 第 2 条并标了「不能用 `git show HEAD:`」——
**假数字比没有数字更坏**，它会让「该重跑的书」被写成「没变」。

**错误 2：留档落点本身是风险。**
`.memory/raw-gates/` **不在 `.gitignore` 里**（`git check-ignore -v` 无输出）
⇒ 429 个留档文件全部进 `git status --short`（当时 289 行里 **288 行**是 raw-gates）
⇒ 在本机「多实例共用目录、禁 `git add -A`」红线下**本身就构成误提交风险**。
处理：全部删除，只留 15 个精准留档。备份在 `/tmp/raw-gates-backup`（已逐文件 md5 校验 429/429 一致）。
