## 一句话启动指令

> **用法**：每本新书开工时，复制下方对应模板填空后发给 agent。
> **关键**：本指令 = 执行规则的核心入口——**每本新书都要先读本文档**，不得跳过。
> **依据**：2026-08-27~09-07 全库 30+ 书审计 + 2026-09-05/06/07 三批跨书互证固化。
> **位置**：本文档保存于 `docs/新书启动模板.md`。

**执行方（精读）**：
```
请先读取 docs/新书启动模板.md，然后按其中的规则执行新书精读。
目标书籍： notes/books/<slug>
开工前额外读取 AGENTS.md（执行规则）和 COLLABORATION.md（并行实例消息），避免重复他人已完成的任务。
```

**审查方（验收，由用户发起时使用）**：
```
请先读取 docs/新书启动模板.md，然后按其中的"独立审查五步法"对《书名》进行审查，报告缺陷清单。
目标书籍： notes/books/<slug>
若书目录不存在或精读尚未完成，先告知用户而非直接开始。
```

## 执行规则（每步必含，不得跳过）

```
精读新书：《书名》（作者），epub 在 notes/books/<slug>/library/

⚠️ 执行规则（每步必含，不得跳过）

0. 任务规划（首条，不得跳过）：
   - 创建 TodoWrite 任务表，列出自 ch01 至 chNN 全章节，
     每条含：章节号 + 简短标题 + 状态（pending/in_progress/completed）
   - 按"三章一批"原则分组（ch01-03 / ch04-06 / ...）
   - 每批 commit 后更新对应条目的 commit hash
   - 上下文压缩后，优先读 TodoWrite 恢复进度，同时重新读取 docs/新书启动模板.md 恢复规则上下文，禁止凭压缩前的记忆继续
   - **修复 / 续接会话同等适用**：接手一本已开工的书，**开工对齐不得整段跳过**——
     先重跑第 0 条任务表对齐 + 第 1 条语料验收，确认进度与 text/ 现状相符再动笔

1. 原文先行：先跑 extract_chapters.py 提取 text/，把章节清单
   （含跳过的书目页/版权页/目录页）发我确认后再动笔
   - **篇目预期数先算清**：版权页发表出处列表 + 目录页 + bullet 实测
     **三方对齐**。对不上先按"合并 / 拆分错误"排查邻居文件，
     **禁止单方宣布"精选本缺篇"**（三选本缺篇判断的经典误报方向）
   - **动笔前跑语料层验收**（AGENTS.md 原文核验第 1a 条）：
     `python3 scripts/verify_corpus.py "<书目录>" --expect N --expect-source "<来源>" --anchors "ch01=甲,乙; ch02=丙"`
     短篇集 / 分部书 / 多 POV / 日历书**必跑 `--anchors`**；单 POV 长篇可省。
     **这一层不过，下面所有门禁的绿都是假的**——不要带着失败的 text/ 动笔

2. 体裁与格式：这是<言情长篇/短篇合集/推理小说/非虚构>，
   按 AGENTS.md 对应格式执行；不确定就先问我

3. 首章试产：先只写 ch01
   - 必须跑 verify_quotes + check_vocab + check_entities
   - 报告必须附工具原始输出（verify_quotes tail -5 + check_vocab FAIL行 + check_entities结果）
   - 我验收格式，通过后你再批量推进

4. 批次节奏：三章一批，每批独立 commit
   - 每批完成后必须先贴工具输出，不贴不继续
   - commit 前第 3 条门禁全绿（verify_quotes / check_vocab / check_entities）
   - 有 text/ 的批次加跑 check_chapter_quotes
   - **漏提交检测（强制）**：每批 commit 后立即跑 `git ls-files <书目录> | wc -l` 与 `git status --short <书目录>` 比对该批应提交数；若有 md 仍显示 `??`（untracked）即漏提交，必须补 `git add` + commit——Aickman 批次 ch11 在批4 未被纳入提交、直到全书收尾才以 untracked 暴露，属漏提交盲区
   - **⚠️ 手工列路径必然漏，提交后必须复核（2026-09-23 用户核出）**：五步审查整改提交 `e01f9ffe` 的 `git add` **手工文件清单遗漏 ch10**（该文件仅改了一行关键词），是逐个列路径时数漏所致。**规则**：一次提交涉及 **10+ 文件时，提交后立刻跑 `git status --short <书目录>`，该书目录零输出才算提交完整**——`ls` 计数或提交成功提示都不算数
   - **⚠️ 「已提交但被他人改写丢失」是另一类，查 `??` 抓不到**（Boyfriend 2026-09-27）：并行实例 rebase/force 把已提交章节甩出历史时，**工作树干净、`ls` 计数也不告警**——完工前须做 **md 件数 == text 件数**对账（见终验清单）

5. 词汇逐条验证（第 8b 条核心）：
   - 每个词条写入前必须 grep 验证："grep -i 'word' text/chNN.txt" 有输出才写
     ——**以本章 text/ 为准，跨篇词条不允许写入**（词在全书他章出现≠本章可收；
      若确需保留，check_vocab 会以 WARN 报"词条跨篇"），例句同理取本章原句
   - 例句直接从原文复制，不改写
   - **禁止添加"（未出现在原文）"等标注绕过工具**
   - check_vocab 报 FAIL=0 不代表词汇干净——工具只检词频，不识别中文标注
   - **「可迁移表达」节的英文同样须逐字取自本章原文**，优先从本章引语块复制
     ——该节不是引语块（无 `>` 前缀、无编号），**任何主门禁都不解析它**，
     是全库最易脱离门禁自造的一层。实测该节在 28 本里覆盖 200 个文件、
     其中 191 个是表格形态，共 846 行；v3 起的 check_vocab 已把这类表格
     排除出词条计数（否则虚高 37%），但**排除不等于校验**——写错的英文
     依然无人发现。
   - 2026-08-30 Barron's 批次实证：52篇928条 A 类虚构靠"（未出现现在原文）"标注绕过工具检测

6. 引语修复同步（第 9 条）：
   - 引语换新句时分析必须同步重写，禁止改引语留旧分析
   - 关键词必须能在引语中找到（允许词形变化）
   - 孤儿块（有分析无引语）和重复块均属缺陷
   - **中文理解/上下文/呼应等全部子项须随引文同步改写**——Aickman ch01 改引文后中文仍写「完全……」、ch06 截断虚构尾巴后中文仍写「房中之房」，均属「改引语留旧分析」的变体，审查时按缺陷处理

7. 总览最后写（**强制，短篇合集除外**，2026-09-18 用户拍板）：
   **除短篇合集外，所有书籍完工时必须创建总览三篇**（概述/金句精选/情感节点）——
   精简格式（推理/悬疑/奇幻）、随笔集、非虚构论述、诗歌回忆录一律适用，
   "精简格式不含总览"不再是可选项；不接受"无总览三篇"的完工通报。
   三篇完成后，交叉核对人物身份/关系/结局/叙事结构，引语逐句 grep 验证

   ⚠️ 总览引语核验是独立门禁（verify_quotes 不覆盖 00_*.md）：
   - verify_quotes 167/167 全绿不等于总览层干净——它是章节级门禁，总览是独立盲区
   - 金句精选/情感节点/概述的每条引语必须逐字 grep epub 验证，不可省略
   - 本次 Aickman 批次实证：verify 全绿但金句精选仍含 6 处改写/虚构（末尾虚构/跨标签拼接/虚构衔接）

   ⚠️ **说话人归属核验（新增，Room 37% 误归教训）**：
   - verify_quotes 全绿 = 引语逐字正确，但说话人/场景可能完全归错
   - Room 金句精选 30 条中 11 条（37%）人物误归：Julia 说的话归给 Astrid，Rudbeck 的话归给 Jonny，Kim 的话归给 Julia
   - 根因：上下文分析/重要性/为什么这样写三子项凭记忆填充，引语本身真实所以 verify 通过
   - **验证方法**：每条引语必须 `grep -n -B10 -A5 "引语关键词" text/chNN_NN.txt` 确认说话人；
     涉及多方的（如 Kim 对 Julia / Kim 对 Rudbeck / Rudbeck 对 Kim）必须 grep 上下文 200 字符窗口二次确认
   - 特别危险：同一人对多人说话（Kim 对 Julia / Kim 对 Rudbeck 语气相似）、多视角叙事中同一描述不同人物；
     凡涉及人物转换的引语，归属置信度必须达到"看到说话人标签"才算数

   ⚠️ **审查报告缺陷须经「读文件定位→grep 原文」二次确认**：
   - 审查方给出的引文偏差（如「bright ones→bright girls」）常只是表象——执行方接到后必须回原文 grep 整句，可能发现更深的虚构衔接（Aickman ch04 报告只指「bright ones」，实际后半句「the ones who might have gone to university」在 epub 完全不存在，属编造衔接）
   - 执行方不得照抄报告结论即改，须独立核实整句；核实后若发现报告未覆盖的额外偏差，一并修复
   - 审查报告编号（⑩/⑬）是审查方自编号，不对应文件章节号——定位缺陷先读文件再 grep，禁止套用报告暗示的映射（Aickman 报告 ⑩=ch01、⑬=ch04，文件里是 ch10/ch13）
   - Room ㉗㉘ "No pain, no gain" / "We should settle this" 在 text/ 完全不存在，
     但 verify_quotes 报 235/235 全绿——直到对 00_*.md 引语做 text/ 全量扫描才发现
     （再次印证上方"总览引语核验是独立门禁"——同一条规则的两种实证）
   - **总览引语必须逐条 grep text/ 验证**，不可跳过；MISS 未必是工具假 MISS（Room 实战两条真实虚构）

   ⚠️ 引文截断与拼接红线：
   - 省略号 `…` 左侧必须是原文原词，右侧不得添加原文不存在的词句
     （例："…four shapely chandeliers; and a room within the room" ← "and a room within the room" 是原文不存在的虚构尾巴）
   - 跨叙述标签拼接禁止：前半句 `"It is necessary that he should come regularly."` + 后半句 `Ursula continued. "Necessary for the clocks."` 不可合并为一句——两段属不同说话标签
   - 虚构衔接禁止：用原文不存在的 bridging 句连接两段真实引文（如 "bright girls…，the ones who might have gone to university" —— "the ones who…" 在 epub 不存在）

   ⚠️ 工具 MISS ≠ 虚构：
   - normalize 拼接脚本对含特殊字符（' / " / ’）或超长句有假 MISS
   - 当工具报 MISS 但逐篇 `find()` 在 epub 原文中能匹配到时，以逐篇 find 为准
   - 可靠验证顺序：逐篇 find（原书）> normalize 拼接 > 报告数字

8. **写作期防缺陷**（每章写完即成立，AGENTS 第 8 条）：
   - **先摘录、后分析**：写每一块前先从 `text/chNN.txt` **复制**原文，再基于摘录写分析
   - **导航/总结层的英文同样只能复制**：`## 本章导航` /「一句话总结」/「读者视角提示」
     **不在六道引语门禁的解析范围内**（实测抽 0 条）——这三层凭印象写即缺陷
     （Jane Eyre 98 条约六成在此；Merry Matchmaker ch21 两处虚构引用全在导航内）；
     写总结前先 `tail` 本章结尾段（AGENTS 8.1 第 4 步）
   - **修复缺陷时引入的英文也要过门禁**：审查/整改时照抄报告里的英文写进分析层、
     未回原文核，**自己新造过 6 处伪造引语**（Jane Eyre）——替换文本**写入前先 flat 比对**，
     改完对该处新写入的英文跑一次 sweep（AGENTS 8.1 第 5 步）
   - **不手打章节结构**：新书按 AGENTS 体裁表选一套子项与配额；接着写**先读上一章照它写**（AGENTS 8.1 第 6 步）
   - **五条禁令**（详见第 8 条 8.2）：引语复制粘贴不手打；不写"N 个词 / N 个分句"这类
     不可核的计数；分析层英文作证据须整段复制；关键词只从本块引语挑；引语只取一个说话轮次
   - 检测脚本（`audit_numbers` / `sweep_analysis_inline` / `check_anchor` / `audit_structure`）
     **改为每批抽查 2–3 章**，不再每章必跑——它们现在的作用是**测量预防是否有效**，
     不是替写作兜底。**FAIL=0 才推进的硬要求只保留在第 3 条提交门禁**
   - 有 text/ 的批次**仍须核逐章归属**（`check_chapter_quotes`；AGENTS 第 9 条 e 项：
     凡有 `text/` 的书一律加跑，不设"100 Great 专用"）——**这一条不降级**：
     跨章搬句是**引用错误**而非表述问题，写作规则防不住

9. 全书完成后（**五步审查由用户主动发起**，2026-09-18 用户拍板）：

### 🕐 门禁时序表（何时跑什么，2026-09-06 固化）

> **🚦 先判 lane**（每批开工第一步）：`ls "<书目录>"/library/*.epub` 有 → **完整 lane**；
> 无 → **降级 lane**。降级 lane 的书**不是"检查通过"，是"部分检查没做"**——
> 引语的 epub 全书口径核不了、词条的「是否虚构」不出结论。报告必须写明 lane。
> **实测（2026-09-26 复核更正）**：全库 355 个书目录中 **100 本（28%）有 epub**，
> 其中**仅 11 本同时有 `text/` + md**（材料完整、门禁能力最全），另 89 本只有
> epub、无 md、无 text/——是**已投喂待精读的新书**。旧文的「11 本（3%）」是错的，
> 根因 `find -maxdepth 3` 而 epub 在第 4 层。
> **「例句是否命中本章」是逐章判定，比对本章 `text/`，两种 lane 都权威，照常判。**

| 时机 | 必跑 | 常见错误 |
|------|------|---------|
| 开工第 1 步 | `extract_chapters.py` → **`verify_corpus.py`**（语料验收，件数/锚点/首末句/转义符体检） | 件数≠章数；短章被 min-len 滤掉未补提；**未跑语料验收就动笔**（语料层错了下面所有门禁会同时假绿） |
```

## 协作板身份与时间戳规范（新增，2026-08-31 实证）

**身份规范**：
- 每个 IDE 实例有固定身份（ZCode-Mac / Opencode-Mac 等），发帖前确认自己是哪个
- **不得修改其他 agent 的消息**——即便发现错误，也只能在自己的新消息里补充说明，不能改动他人已发布的内容
- 交接时须核对 COLLABORATION.md 最新消息的身份前缀，避免串改

**时间戳规范**：
- 发帖前必须运行 `date -u '+%Y-%m-%d %H:%M UTC'` 查实当前 UTC 时间
- 不得估算、记忆、捏造时间戳；时间错误会使协作板排序失效

**原因**：2026-08-31 本会话 ZCode-Mac 误将 Opencode-Mac 的合法消息改为己出，并捏造时间戳 11:20 UTC（实际 10:59 UTC），经用户指出才更正。

**消息频率与内容规范（2026-09-15 新增）**：
- **每书每 agent 只发一条消息**——在"全书完工 + 审查通过"时一次性发布，包含：精读文件数、门禁数字（第 3 条全量）、commit 计数、当前状态（待 push / 待审查）
- **开工 / 批次进度消息不进协作板**——这些信息已在 `git log` 中，不需要重复占用协作板顶部位置
- **唯一例外**：发现可能影响并行实例工作的重大问题时（如章节映射有误、发现跨书共享角色名、文件命名冲突等）才能追加消息，说明问题而非重复进度
- **违反后果**：一本书发多条（开工 → 批2 → 批3 → ... → 完工 → 审查）会让协作板堆满过时快照，且多条消息时间戳各异，难以判断真实的新旧关系

**理由**：协作板是"当前有效状态"的快照，不是进度直播。一本书的完整信息只需要一条消息就能表达（完工时）；中间任何时间点想知道进度查 `git log` 即可。

**内容精简原则**：
- 协作板消息只写"当前状态摘要"（文件数、门禁数字、commit 计数、待 push）
- **详细过程（发现的问题、调试步骤、修复内容）全部写入 `daily/YYYY-MM-DD.md`**，不写进协作板
- 当用户提出更新协作记录或工作日志时，**先查 `daily/` 和协作板是否有这本书的已有条目**——有则直接在已有条目中更新内容 + 更新时间，不用重开一条

**⚠️ 更新时机（2026-09-18 用户拍板）——两个节点，第二次就地改**：
1. **书籍完成之后、五步审查之前**：同步更新协作记录（COLLABORATION.md 发本书唯一完工通报）+ 工作日志（`daily/YYYY-MM-DD.md` 记本书条目，含章节数、门禁数字、commit 清单）
2. **独立五步审查之后**：把审查结论（审查方 / 缺陷数 / 整改 commit / 结论档位）**追加进同一条协作板消息与同一篇日志的本书条目内**——**就地编辑，不新开条目**（不新发协作板消息、不新建日志段落）；更新该条的时间戳
3. **此后再有额外修复记录**（后续审查整改、问题修复、补做章节等）：再就地更新一次同一条目；**不再要求 push 前逐本标注"已推送"**——push 常为多本书统一执行，逐本标记不可行

**理由**：协作板消息过长（超过 20 行）是无意义的——详细过程只有写的人自己需要回顾，写进 daily 是长期存档，写进协作板只会让后来查协作板的人难以快速获取有效信息。

## 词汇 A/B 类裁决规范（第 5 条核心）

check_vocab 报 FAIL 时，先以 epub 展平全文终极裁决：

| 类别 | 判断标准 | 处理方式 |
|------|---------|---------|
| **A 类：真虚构** | epub 展平全文也查无此词 | 用文中真实词替换，禁止删除了事 |
| **B 类：语料缺失** | epub 有但 text/ 提取件缺 | 优先改用文中真实词形，或重跑 extract_chapters.py 修复提取覆盖 |

**判 A 前置动作（2026-09-22 新增）**：flat **整串**查无 ≠ A 类——必须先拆 fragment 分段取证（各片段分别 flat 查 + 前后文 ~150 字符窗口 grep），排除跨标签拼接后才可定 A。实证：She Haunts 9 条整串查无中 7 条是拼接（两半逐字都在原文、中间叙述标签被换句号），直接判 A 类会误杀真引语。

**禁止**：不裁决直接删词条；不裁决直接加"（未出现在原文）"标注了事。

## 编号规则与防混淆规范（2026-08-31 新增）

本系统存在 **三套独立编号体系**，必须严格区分，禁止混用：

### 三套编号体系

| 编号体系 | 格式 | 作用域 | 重置规则 | 示例 |
|---------|------|--------|---------|------|
| **引文块编号** | `> **原句 N:**` | 同一精读文件内 | 同一篇内连续不重置 | ch01 中 `原句 1` → `原句 2` → … |
| **金句精选编号** | `⑩`（圆圈数字） | 全书金句精选.md | **不重置**，全书排序 | ㉑、㉒、㉓ … |
| **情感节点编号** | `节点一` / `节点 N` | 全书情感节点.md | **不重置**，全书排序 | 节点一、节点二 … |
| **审查方自编号** | `⑩` / `⑬` | 仅在 COLLABORATION.md 审查报告中 | 临时，**非文件编号** | 仅用于定位缺陷，不等于 ch10/ch13 |

### 关键约束

1. **引文块编号 ≠ 金句编号**：同一篇 story 的引文块编号从 1 开始，金句编号按全书排序。例如 ch01 引文块 ③，不等于金句③。
2. **金句编号不重置**：短篇合集约 25-30 句，全书排序；不同篇可以有相同的"原句 N"但金句编号全体系唯一。
3. **情感节点与金句独立编号**：两者都用圆圈数字但属不同文件，不可混淆。
4. **审查方自编号 ≠ 文件章节号**：审查报告中的"⑩"是审查方为方便引用而自编的序号，**不对应任何文件中的章节号**。发现缺陷后必须先读文件定位，再 grep 原文确认——禁止直接套用报告暗示的章节映射。

   **实证**：Aickman 审查报告中"⑩=ch01"、"⑬=ch04"——⑩ 对应金句精选第 10 句（ch01 的引文），而非文件中的 ch10；⑬ 对应第 13 句（ch04 的引文），而非 ch13。

5. **COLLABORATION.md 中引用格式**：缺陷定位必须包含文件名 + 实际章节 + 引文内容片段，禁止只写"金句⑩有问题"而不说明具体文件和章节。
   - ✅ `金句精选.md ⑩（ch01 第 1 句）`
   - ❌ `金句⑩`

### 其他易混淆规则

| 规则 | 常见混淆 | 正确做法 |
|------|---------|---------|
| verify_quotes 主口径 | 以为总览层也受其保护 | verify_quotes 只管 `chNN.md`，**不覆盖** `00_*.md`（总览三篇） |
| check_vocab FAIL=0 | 以为词汇表已干净 | 工具只检词频，不识别中文标注；Barron's 批次 FAIL=0 时仍有 928 条 A 类虚构；**Ligotti ch33 nullify/ch52占位符/ch73 night 在别章出现即过 FAIL，但例句是虚构** |
| check_vocab 逐章验证 | 以为全书词频口径够用 | **必须逐章 grep 验证例句**，不能只看 FAIL 数字——A 类虚构在书的其他章出现，check_vocab 不会报 FAIL |
| check_chapter_quotes.py | 以为只针对 100 Great | AGENTS.md 第 9e 条：**凡有 text/ 的书一律加跑**，不设例外；**Ligotti ch22 PLACE heading** `"the diseased waters await his embrace"` flat 匹配失败（原文有 whose），属工具假 MISS，非引语虚构 |
| check_chapter_quotes flat 匹配 | 以为 MISS 都是引语虚构 | 工具按 `re.sub(r'[^a-z0-9]', '', s.lower())` 规范化后匹配，省略号/标点差异导致假 MISS；**以 `grep -i "phrase" text/chNN.txt` 人工确认为准** |
| "引语逐字" | 只验证引语行，不验分析/词汇层 | 第 9 条修复同步规则：引语换新句时分析/关键词/中文理解全须同步重写 |
| 省略号截断 | 以为只要有 `…` 就是合法截断 | `…` 左侧必须是原文原词，**禁止在右侧添加原文不存在的词**（gilding） |
| git add -A | 多 IDE 并行时方便 | **禁止** `git add -A` / `git add .`——只 add 明确路径清单 |
| 旧格式圈数字转换 | 以为转换后自动编号正确 | **Ligotti 49 章转换后 ch22/ch27/ch28/ch29 全部残留 `原句1`**（映射逻辑 `①→1` 后对所有圈数字重复执行替换）；转换后必须检查编号是否连续递增 |

### 2026-09-27 Library of Heartbeats 五步审查新增坑（**死代码让自建检查器静默失效**）

| 条目 | 对应事故（实证） |
|------|----------------|
| ⚠️ **自建检查器的死代码**（本轮最有价值的一条） | `scripts/attic/xref_check.py` 写成 `if nf in allc: continue` 之后**又**跟了一段归属检查——`continue` 使其后整段**永不可达**。后果：该脚本只抓「凭空造词」，**从不抓「引语真实但章号标错」**，而后者是更常见更危险的一类。同一本书修复前报 2 条、修复后报 40 条，剔假红得 20 条真缺陷。**教训：审查期现写的检查器必须先自证「每条分支都可达」**——最省事的自证是「故意注入一个已知缺陷，看它报不报」（本轮即用 ch08:35 的 `The new, for Shūichi, was an unbearable risk.` 注入验证） |

| **成句级引用要拆句给各自章号** | 3 处一行里塞了两个不同章的引语（ch01:47 `Ōmachi/Komachi/Inamuragasaki` 在 ch03 但 `Koda-san` 在 ch04；ch13:67 `a puddle of sea` 在 ch01 而 `two days of unexpected autumnal warmth` 在 ch02）。**修法是拆成两句各标各章，不是改其中一个章号** |
| **总览引语章号 ≠ 条目章节标签** | `check_overview_full` 报「标注 ch13 但引语在 ch15」，实为**行内的解读性关联**（「这两句正是 ch13 门口那块题词的注脚」），条目自身 `**上下文**：ch15` 正确。**行内 chNN 可能是呼应关系而非出处**——人判时先看条目自身的上下文标签 |
| **`check_overview_full` 的「多重命中」多为真实现象** | `TO BE HAPPY, FIRST OF all you need to imagine being happy` 报「ch09,ch17 歧义」，grep 确认**两处都真实存在**（ch09 母亲所教、ch17 秀一重述）。标注取首出处 ch09 正确。**同一句在书中被复述是本书的题眼手法，不是缺陷** |
| 禁止标注的第二个变体 | ch09/ch11 的「（取自目录页的日文拟声词，正文未出现）」——`check_vocab` 的 `FORBIDDEN_ANNOT` 宽口径检出（只报不判红）。**它确实违反 AGENTS 第 5 条**（禁写「未出现」类标注），但违规点不在词表而在**分析层的括注**。修法：改成正面表述「（目录页作「Part One: ばくばく baku baku」）」——`baku baku` 确在 epub 的 `007-Part_1.xhtml` 与 `toc.ncx` |
| 词表冠词化词头会**分批复发** | 本轮修 9 处（`a/an + 名词` → 裸形），但**下一批又出现 5 处**。原因：前批是「逐条修」，没建机制。**根治＝用 `vocab_candidates.py` 从 `text/` 产出词头**（AGENTS 8.5 已确立该脚本能消灭此类缺陷） |
| `Tokyo` vs `Tōkyō` 的 grep 假阴性 | 概述时间线「东京艺大」grep ASCII `Tokyo` 查无，原文实作 `Tōkyō`（长音 ō）。**专有名词含长音/变音符时，grep 必须同时试 NFC/NFD 两种形式** |
| dropcap 粘连是 `text/` 侧的系统性提取缺陷 | `A German heart` 在 `text/` 是 `AGerman heart`（首字母 dropcap 未分离），epub 真值为 `A German heart`。凡首词两字母以上且首字母大写时，`text/` 命中失败须先对 `OPS/*.xhtml` 取证再判 md |
| 译者署名不是跨书污染 | 总览里出现 `JOEL AGEE` 疑为《All Our Yesterdays》作者串入，grep 取证为 Canetti《The Secret Heart of the Clock》译者署名（ch07 末尾 `TR. JOEL AGEE`）。**跨书污染自检的假红来源之一：译者/编者/机构名** |
| ⚠️ **「子代理说它在 chNN」不等于「它存在」**（本轮最险的一条） | 我凭印象造了英文 `This is a journey you take to listen to someone's heart.` 并用了三处。批次2 子代理报「该句在 ch06」，我据此把 ch15:15 的章号从 ch11 改成 ch06——**把一处错标改成了另一处错标**，而错误依据本身是伪造的。**跨章旁证要过两关：① 该句在所标章逐字存在 ② 章号对**；顺序不能反，先信子代理的归属结论会跳过第①关 |
| **同一个错误在总览与正文章节各写一遍** | 00_情感节点:33「撞上白车／缝了二十针／三十五岁」与 ch09:67「三十五岁问母亲」是同一处错误的两个副本。总览层不受任何逐章门禁约束，**正文章节改了总览不会跟着改** ⇒ 整改后必须回头 grep 总览三篇里同一个人物/时间/事件的表述 |
| 词数断言在**同位语长句**上最易错 | 三处同型：`A supernatural creature, Shingo, his beloved boy-fish, would live forever.` 断言「四个逗号」实为 3；`All around them, chimes tinkle gently and the wind whispers names.` 断言「十四个词」实为 11。**AGENTS 禁令 2 禁「N 个词」的理由在此得到又一次印证**——当场数得对也容易错，何况多数是凭印象 |
| **引语与分析自相矛盾（引语里明明写着）** | ch12:37 引语是 `Shūichi continued, laughing.`，分析却写「注意秀一**没有笑**」。这类**不需要外部取证**——引语就在块顶上一行，人扫一遍就能抓到，四个子代理里有一个抓到了 |
| 事实错误的**并列句式**会互相传染 | ch11:11 一句导航里 4 处错（四天/三天、发烧住院/祖母住院、沾满泥渍/洗干净、下水那天丢/沙滩上丢）。**一个长句一旦有一处错，往往不是孤例**，改的时候要把整句拆开逐项核 |
| 子代理误报的两条纯幻觉有共同形态 | ch14:15 声称本文件写「全章对白只有三句」、ch02:57 声称写「ch14 里老年他蹲进黑暗的房间」——都是**声称我写了某句实际不存在的话**。此类报警**可机械核**：`grep '<原句片段>' <md>` 为 0 即幻觉，建议 d 步 SOP 对这一类直接先 grep 再读 |

| 概述里写「本章」= 指代失效 | 00_概述 的 Kenta 条目写「本章新父亲」——概述不是章节，无「本章」。另 Aya 条目原写「她在 ch08 与 ch12 两处出场」，grep 实测 ch05–ch17 共 5 章提及。**人物弧光条的出场章数须 grep 全书复核，不能凭印象** |
