# 书籍开工卡（原「新书精读启动指令模板」）

> **用途**：一本书开工时，复制下面两段指令之一发给 agent。
> **规则正文不在这里**：写作 → `docs/rules/创建卡.md`；门禁判读 → `docs/rules/20-gate.md`；审查 → `docs/rules/审查表.md`。
> 本文件只保留**书级编排（0–9 步）· 体裁格式表 · 编号规则**（2026-10-20 拆分，见 `docs/rules/PLAN.md`）。

## 一句话启动指令

**执行方（精读）**：
```
开工：《书名》（作者），epub 在 notes/books/<slug>/library/（或 notes1/books/<slug>/）。
先读 docs/rules/创建卡.md（写作规则与一章骨架），再按 docs/新书启动模板.md「执行规则」的 0–9 走（只读那一节，不要整份通读）。
写之前只跑这一条拿到全部契约：python3 scripts/bookform.py "<书目录>" --contract
  （会判红的 8 项 / 不判红的 / 一章骨架与本书体裁的导航项名，全在里面。**不要读 scripts/ 源码反推判据**。）
引语是句级：每块 1–3 句、30–70 词；chapter.sh 对 >100 词的块打 ⚠️，看到就按原文句界拆。
块数每章 2–15 块（>15 或 <2 判红）；chapter.sh 会给出本章按词数的建议区间（约每 1,000 词 2–4 块）。
每章必含 `## 本章词汇`（三档表，例句逐字取自本章 text/）。
派子代理时按 docs/rules/子代理派工.md 给料（创建卡 + 本章 text + 上一章形态，不给审查表）。
动笔前先交素读清单：python3 scripts/suread.py "<书目录>" chNN "<facts.txt>"（5–8 条事实 + 原文锚点，查无即打回）。
每章写完：bash scripts/chapter.sh "<章 md>"，rc=0 立刻提交本章；每批 commit 前：bash scripts/gate.sh "<书目录>"。
全书完工前：跑 T1 自检（创建卡 §6.1，约 33 分钟）——总览三篇全篇人判 + 抽 ceil(N/8) 章 + assertion_scan 六类预筛；
  产物 t1-verdict.md / t1-candidates.txt / 台账一行（审查方填 `自检`）。**三件缺一不算完工**；查出 ≥3 条阻断自动进 T2。
```

**审查方（用户发起时）**：
```
对 notes/books/<slug> 执行审查：先读 docs/rules/审查表.md（§0 四档 T0–T3）与 docs/rules/生产-审查对照.md（按生产步骤打靶）。
档位：**默认 T1 快审**（30–35 分钟）——T0 机器层全量 + 总览三篇全篇人判 + 章内抽 ceil(N/8) 章（2–6 章，首末必含、其余等距）。
       T1 查出 ≥3 条阻断（或同一成因类 ≥2 章复现）⇒ **自动进 T2 断言全扫**（60–90 分钟），不必请示；
       T2 之后仍有 S1/S2 层信号（漏读原文 / 引语截短 / 跨段拼接 / 块数形态异常）才请示 T3 深审（150–240 分钟）。
       **不许把 T1 直接膨胀成 T3**。
铁律：先素读 text/chNN.txt 写素读清单；写完才打开 md；违反则本次结论作废。有 production/chNN-suread.json 的
       抽样章可复用（跑 suread.py 验锚点全命中 → 抽 2–3 条回源 → 重点读引语邻域），并额外问「本章转折点进没进这几条」。
机器层全量：bash scripts/gate.sh "<书目录>"；总览另跑 python3 scripts/overview.py quotes / full "<书目录>" "<epub>"；
       含 `…` 的引语块用 verify_fragments_indep.py 逐段独立取证（整串 flat 比对救不了拼接）。
T2 取候选：python3 scripts/assertion_scan.py "<书目录>"（六类成因；①②③⑥ 读全量，④⑤ 各抽 20 行）。
人判：按章型抽（首章 / 重述章 / 对话密集章 / cliffhanger 章 / 末章）+ **总览三篇全篇**；
      每章一句话总结按六类预筛，只读命中行——**不要逐章全读回源**（O(章数)，49 章书要 40 分钟）。
编排：**审查串行做，不按章派子代理**——管理成本会超过审查本身（实测 39 个子代理 / 20.8 小时 / 0 产出）；
      子代理只用于生产起草，且必须给派工卡的四件给料。
取证：每条阻断必须给 text/<文件>:<行> 与原文逐字。写「查无」必须贴命令+输出+退出码，
      用 /usr/bin/grep 显式路径——**不用 git grep**（text/ 被 .gitignore 排除，恒空且退出码与「真查无」不可区分）。
产物（T1）：.memory/raw-gates/<slug>/review/t1-verdict.md（**第一行写抽样章号与理由**、末行写读了哪些候选行）
      + t1-candidates.txt（assertion_scan 原始输出）；T3 深审才用 chNN/ 四件套（1-suread / 2-machine / 3-diff / 4-verdict）。
      4-verdict.md 末尾固定写「已核实为正确」节（防下一轮把对的改坏）。
      落盘纪律：raw-gates 只放结论层（判定表 / 素读 / 机器层 / 指令）；探针、临时脚本、中间转储写 /tmp，不要入库。
记账：.memory/review-ledger.md 追加一行，**「审查方」列填 `异会话`**（自检由写作方在完工前填 `自检`）。
覆盖：报告写明人判覆盖（如「T1 抽样 4/37 章 + 总览三篇」）；只有机器层的章写「仅机器层」，不许含混成「已审查」。
分工：默认只出指令不改稿，修复由执行方做；收到执行方回执后再验「改没改、有没有改坏」。
若书目录不存在或精读尚未完成，先告知用户，不要直接开始。
```

## 执行规则（0–9 编排）

> 本节只管**顺序**。每一步的判据都在对应文件里，需要时按 `AGENTS.md` 路由去读，别在这里找细则。

0. **任务规划**（首条，不得跳过）：建任务表列 ch01–chNN；按 `docs/rules/30-writing.md` 的批次节奏分组（按产出体量，长篇约 1 章/次；**不是「三章一批」**）；每批 commit 后回填 hash；**上下文压缩后先读任务表 + 创建卡恢复**，不要重读本文件。
   修复 / 续接会话同等适用：先对齐任务表 + 重跑语料验收，确认进度与 `text/` 相符再动笔。
1. **原文先行**：`extract_chapters.py` 出 `text/`；预期篇目数用「版权页发表出处 + 目录页 + bullet 实测」**三方对齐**；**动笔前跑 `verify_corpus.py`**（判据见 `30-writing.md` 1a 条）。
2. **体裁**：这是<言情长篇 / 短篇合集 / 推理 / 非虚构>；形状看下节 profile，不确定就问。
3. **首章试产**：只写 ch01 → `bash scripts/chapter.sh "<章 md>"`，报告附尾部与退出码（**rc=2 是「无法判定」，不是通过**）；用户验收后再批量推进。
4. **每批收口**：贴工具输出 → `bash scripts/gate.sh "<书目录>"` 退出码 0 → 红了按 `20-gate.md` 四档定性 → commit → **漏提交对账：书目录 + `.memory/raw-gates/<slug>/` 两处零输出**（见 `20-gate.md` §5）。
5. **词汇**：每个词条写入前 grep 本章 `text/`，例句复制不改写（判据与 A/B 裁决见 `30-writing.md`）。
6. **引语修复**：换引语必须同步重写全部分析子项（全文见 `11-fix-sync.md` 第 9 条 a–h）。
7. **总览最后写**（短篇合集除外）：三篇必做；引语逐条 grep + 说话人归属核验（判据见 `30-writing.md`「总览三篇」；门禁见 `20-gate.md`）。
8. **写作期防缺陷**：先摘录后分析；导航 / 总结层的英文也只能复制（细则见 `30-writing.md` 8.1–8.5）。检测脚本改为**每批抽查 2–3 章**（`audit_numbers` / `sweep_analysis_inline` / `check_anchor` / `audit_structure`）——它们测的是预防有没有效，不是替你兜底；`quotes.py chapter` 的逐章归属**不降级**。
9. **完工**：门禁自审（`gate.sh` EXIT=0）+ 总览门禁 + **T1 自检**（`创建卡.md` §6.1，2026-10-24 起属完工定义：总览三篇全篇人判 / 抽 `ceil(N/8)` 章 / `assertion_scan.py` 六类预筛 / 复用素读清单；三件产物缺一不算完工）。
   T1 查出 ≥3 条阻断 ⇒ **自动进 T2 断言全扫**（60–90 分钟）；**T3 深审不自行启动**，报告写「T1 同会话自检（抽 N/M 章，查出 X 条）；T3 深审未做（待用户发起）」。
   报告后等指令再 push（push 红线见 `AGENTS.md`）。

## 体裁与结构 profile（结构约束的唯一定义在 `docs/rules/genre-profiles.json`）

> 结构判据的**唯一定义**是 `docs/rules/genre-profiles.json`，脚本直接读它；下表只解释「怎么读」，不重复判据。**改约束只改 json**。（为什么改成这样见 `docs/实测档案/X_2026-10-20_规则体系审计与重构依据.md`）

| 体裁（＝书目录的父目录名） | 导航 | 子项 | 块数（新书前 3 章） | 必备节 | 总览 |
|---|---|---|---|---|---|
| `novels` | 5 项 | 4 项（含「读者视角提示」） | 3–10 | 本章导航 / 精读 / 本章词汇 / 一句话总结 | 3 篇 |
| `mystery-thriller` | 5 项（第 3 项常换「线索结构」） | 4 项 | 3–10 | 同上 | 3 篇 |
| `short-story-anthologies` | 3–6 项，项名按集子性质自定 | 5 项（含「句子结构 / 表达方式」） | 3–10 | 精读 / 本章词汇 / 一句话总结 | **0 篇** |
| `non-fiction` | 无（改用 `## 概览`） | 5 项（同上） | 5–10 | 概览 / 论证结构 / 选择性精读 / 词汇分级 / 一句话总结 | 3 篇 |
| 其他目录 | 5 项 | 5 项 | 3–8 | 同 `novels` | 3 篇 |

**执行**：`python3 scripts/bookform.py "<书目录>"` 会打印本书 profile（体裁 / 子项数 / 块数区间 / 总览篇数）。
**新书前 3 章按 profile 判**；满 3 章后按**本书自己的众数**判，profile 降为参照。
**偏离 profile 不算错**，但要在判定表写一行理由——形态是这本书的选择，不是全局标准。

**⚠️ 短篇合集没有总览三篇**（用户 2026-09-18 拍板、2026-10-20 复述确认）：全库 24 本里 21 本没有 `00_*`。
另外，`sometimes-i-scare-myself`（三部中篇合集）经用户 2026-10-14 单独拍板豁免，**后续勿据「总览强制」补写**。

### 块数配额＝同书自校准（`11-fix-sync.md` 指向的就是这一段）

**同书自校准，不是「3–8」**（2026-10-18 全库 404 本实测：实际分布 3–29，`burn-for-you` / `the-tenants`
本书中位 3、`theres-something-about-mira` 29 ⇒ 一刀切 3–8 两端都误判）。
profile 的块数区间**只用于新书前 3 章**（还没有可信众数时），满 3 章即以本书中位为准。
