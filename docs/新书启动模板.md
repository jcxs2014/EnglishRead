# 新书精读启动指令模板

> 用途：每本新书开工时，复制下方模板填空后发给 agent。
> 依据：2026-08-27/29 全库 24 书审计暴露的全部失败模式（编号混乱、格式漂移、后期质量衰减、总览虚构等）。
> 配套规则：AGENTS.md 第 8 条（第一遍内联验证）、第 9 条（引语修复同步规则）。

## 启动指令（复制后填空）

```
精读新书：《书名》（作者），epub 在 notes/books/<slug>/library/

⚠️ 执行规则（每步必含，不得跳过）

1. 原文先行：先跑 extract_chapters.py 提取 text/，把章节清单
   （含跳过的书目页/版权页/目录页）发我确认后再动笔

2. 体裁与格式：这是<言情长篇/短篇合集/推理小说/非虚构>，
   按 AGENTS.md 对应格式执行；不确定就先问我

3. 首章试产：先只写 ch01
   - 必须跑 verify_quotes + check_vocab
   - 报告必须附工具原始输出（verify_quotes tail -3 + check_vocab FAIL 行）
   - 我验收格式，通过后你再批量推进

4. 批次节奏：三章一批，每批独立 commit
   - 每批完成后必须先贴工具输出，不贴不继续
   - commit 前三件套全绿（verify_quotes / check_vocab / check_entities）
   - 有 text/ 的批次加跑 check_chapter_quotes

5. 遵守 AGENTS.md 第 8 条（边生成边验证）和第 9 条（修复同步）：
   引语换新句时分析必须同步；每章写完立即 grep 验证词汇真实存在

6. 总览最后写：概述/金句/情感节点完成后，
   交叉核对人物身份/关系/结局/叙事结构，引语逐句 grep 验证

7. 完成后：跑 audit_book 总账，报告三件套数字，等指令再 push

⚠️ 报告违规：禁止在未运行工具的情况下声称"验证通过"、
"全部绿了"、"commit 完成"——每条完成声明必须附原始工具输出。
```

## 强制工具输出示例（复制到报告模板）

每批完成后报告格式：
```
=== chXX-chYY 批次完成 ===

verify_quotes：
$ python3 scripts/verify_quotes.py "<书目录>" "<epub>" 2>&1 | tail -3
[粘贴工具输出]

check_vocab：
$ python3 scripts/check_vocab.py "<书目录>" 2>&1 | grep FAIL
[粘贴工具输出]

commit: [commit hash]
```

## 可选补充项（按书情况追加）

| 情况 | 补充指令 |
|------|---------|
| 多卷 / 多 POV | "双视角，每章标注 POV" |
| 有特定学习关注点 | "我主要想学它的<对话/描写/论证>，分析侧重这里" |
| epub 章节合并/拆分异常 | "提取后打印章节清单，编号映射先跟我对齐" |
| 敏感内容风险 | 依赖 AGENTS.md MiniMax 1027 规则，无需额外指令 |
| 续作 / 同作者第二本 | "格式与《前一本》保持一致，对照其文件结构" |

## 每条挡住的历史坑

| 条目 | 对应事故（实证） |
|------|----------------|
| 1 章节清单确认 | Venus Fly Trap 文件号与 Chapter 号差 1；TWF ch29/31 映射混乱；Eleventh Hour front matter 取舍；The Giver epub 23 章合并为 3 个 HTML |

| 7 audit 总账 + 等指令 push | push 策略：批次定稿后统一推送 |
| ⚠️ 报告违规（Astonishing 教训） | ch51-ch75 只写文件不跑工具，直接报"全部绿了"——无工具输出 = 无完成声明；后续补做消耗更多时间 |
