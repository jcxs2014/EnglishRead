# 书籍开工卡（原「新书精读启动指令模板」）

> **用途**：一本书开工时，复制下面两段指令之一发给 agent。
> **规则正文不在这里**：写作 → `docs/rules/创建卡.md`；门禁判读 → `docs/rules/20-gate.md`；审查 → `docs/rules/审查表.md`。
> 本文件只保留**书级编排（0–9 步）· 体裁格式表 · 编号规则**（2026-10-20 拆分，见 `docs/rules/PLAN.md`）。

## 一句话启动指令

**执行方（精读）**：
```
开工：《书名》（作者），epub 在 notes/books/<slug>/library/（或 notes1/books/<slug>/）。
先读 docs/rules/创建卡.md（约 3 KB，写作规则与一章的骨架全在里面），再按 docs/新书启动模板.md「执行规则」的 0–9 走（只读那一节，不要整份通读）。
章的形状（导航几项 / 子项集 / 块数 / 要不要总览）以 python3 scripts/bookform.py "<书目录>" 第一行为准，别照记忆写。
每章必含 `## 本章词汇`（三档表，例句逐字取自本章 text/）。
每章写完：bash scripts/chapter.sh "<章 md>"；每批 commit 前：bash scripts/gate.sh "<书目录>"。
```

**审查方（用户发起时）**：
```
对 notes/books/<slug> 执行五步审查：先读 docs/rules/审查表.md（R0–R5 全流程）与 docs/rules/生产-审查对照.md（按生产步骤打靶）。
铁律：先素读 text/chNN.txt 写 1-suread.json，写完才打开 md。
机器层全书全量跑；人判层按章型抽（首章 / 重述章 / 对话密集章 / cliffhanger 章 / 末章）。
产物落 .memory/raw-gates/<slug>/review/chNN/。
若书目录不存在或精读尚未完成，先告知用户，不要直接开始。
```

## 执行规则（0–9 编排）

> 本节只管**顺序**。每一步的判据都在对应文件里，需要时按 `AGENTS.md` 路由去读，别在这里找细则。

0. **任务规划**（首条，不得跳过）：建任务表列 ch01–chNN；按 `docs/rules/30-writing.md` 的批次节奏分组（按产出体量，长篇约 1 章/次；**不是「三章一批」**）；每批 commit 后回填 hash；**上下文压缩后先读任务表 + 创建卡恢复**，不要重读本文件。
   修复 / 续接会话同等适用：先对齐任务表 + 重跑语料验收，确认进度与 `text/` 相符再动笔。
1. **原文先行**：`extract_chapters.py` 出 `text/`；预期篇目数用「版权页发表出处 + 目录页 + bullet 实测」**三方对齐**；**动笔前跑 `verify_corpus.py`**（判据见 `30-writing.md` 1a 条）。
2. **体裁**：这是<言情长篇 / 短篇合集 / 推理 / 非虚构>；形状看下节 profile，不确定就问。
3. **首章试产**：只写 ch01 → `bash scripts/chapter.sh "<章 md>"`，报告附尾部与退出码（**rc=2 是「无法判定」，不是通过**）；用户验收后再批量推进。
4. **每批收口**：贴工具输出 → `bash scripts/gate.sh "<书目录>"` 退出码 0 → 红了按 `20-gate.md` 四档定性 → commit → **漏提交对账：书目录 + `.memory/raw-gates/<slug>/` 两处零输出**（见 `20-gate.md` §5）。
5. **词汇**：每个词条写入前 grep 本章 `text/`，例句复制不改写（判据与 A/B 裁决见 `30-writing.md`）。
6. **引语修复**：换引语必须同步重写全部分析子项（全文见 `11-fix-sync.md` 第 9 条 a–h）。
7. **总览最后写**（短篇合集除外）：三篇必做；引语逐条 grep + 说话人归属核验（判据见 `30-writing.md`「总览三篇」；门禁见 `20-gate.md`）。
8. **写作期防缺陷**：先摘录后分析；导航 / 总结层的英文也只能复制（细则见 `30-writing.md` 8.1–8.5）。检测脚本改为**每批抽查 2–3 章**（`audit_numbers` / `sweep_analysis_inline` / `check_anchor` / `audit_structure`）——它们测的是预防有没有效，不是替你兜底；`quotes.py chapter` 的逐章归属**不降级**。
9. **完工**：门禁自审 + 总览门禁；**不自行启动五步审查**、不生成任务书，报告注明「五步审查未做（待用户发起）」；报告后等指令再 push（push 红线见 `AGENTS.md`）。

## 体裁与结构 profile（结构约束的唯一定义在 `docs/rules/genre-profiles.json`）

> 结构判据的**唯一定义**是 `docs/rules/genre-profiles.json`，脚本直接读它；下表只解释「怎么读」，不重复判据。**改约束只改 json**。（为什么改成这样见 `docs/实测档案/X_2026-10-20_规则体系审计与重构依据.md`）

| 体裁（＝书目录的父目录名） | 导航 | 子项 | 块数（新书前 3 章） | 必备节 | 总览 |
|---|---|---|---|---|---|
| `novels` | 5 项 | 4 项（含「读者视角提示」） | 3–10 | 本章导航 / 精读 / 本章词汇 / 一句话总结 | 3 篇 |
| `mystery-thriller` | 5 项（第 3 项常换「线索结构」） | 4 项 | 3–10 | 同上 | 3 篇 |
| `short-story-anthologies` | 3–6 项，项名按集子性质自定 | 5 项（含「句子结构 / 表达方式」） | 3–10 | 精读 / 本章词汇 / 一句话总结 | **0 篇** |
| `non-fiction` | 无（改用 `## 概览`） | 5 项（同上） | 5–10 | 概览 / 论证结构 / 选择性精读 / 词汇分级 / 一句话总结 | 3 篇 |
| 其他目录 | 5 项 | 5 项 | 3–8 | 同 `novels` | 3 篇 |

**执行**：`python3 scripts/bookform.py "<书目录>"` 会打印本书 profile（体裁 / 子项数 / 块数区间 / 总览篇数）。
**新书前 3 章按 profile 判**；满 3 章后按**本书自己的众数**判，profile 降为参照。
**偏离 profile 不算错**，但要在判定表写一行理由——形态是这本书的选择，不是全局标准。

**⚠️ 短篇合集没有总览三篇**（用户 2026-09-18 拍板、2026-10-20 复述确认）：全库 24 本里 21 本没有 `00_*`。
另外，`sometimes-i-scare-myself`（三部中篇合集）经用户 2026-10-14 单独拍板豁免，**后续勿据「总览强制」补写**。

### 块数配额＝同书自校准（`11-fix-sync.md` 指向的就是这一段）

**同书自校准，不是「3–8」**（2026-10-18 全库 404 本实测：实际分布 3–29，`burn-for-you` / `the-tenants`
本书中位 3、`theres-something-about-mira` 29 ⇒ 一刀切 3–8 两端都误判）。
profile 的块数区间**只用于新书前 3 章**（还没有可信众数时），满 3 章即以本书中位为准。
