# 门禁反例库

> **定位**：门禁报警的**定性记录**——每一条报警属于哪一档、为什么、处置是改 md / 改工具 / 只记，
> 以及它触发了哪条规则或哪个工具的变更。
>
> **与 `docs/禁令实测档案.md` 的分工**（两根轴，不重叠）：
> - 禁令实测档案 = **写作期预防**——缺陷在「动笔那一刻」怎么产生的（禁令 1/1a/1b/1c/2/3/4/5）
> - 本库 = **检出期定性**——报警落地后属于哪一档，以及它暴露的是内容缺陷还是工具故障
>
> **为什么要有本库**（原 P2-5 是「逐书报警台账 `gate_log.md`」，已改定义）：
> 逐书台账是**检查型的产物**——8.5 已证检查型规则不减少缺陷（补齐「逐条验」后
> 词表初稿缺陷率仅 43%→42%），而台账只记「报了什么、怎么处置」，
> **不回答「为什么会报」**。同一类报警在 40 本书里重复 40 次，
> 逐书记 40 遍；归到这里记 1 遍，并指向它触发的规则/工具变更。
>
> **判据**：AGENTS 第 3 条「🚦 门禁结论必须分三档」。本库是那张表的证据底座。
> 那句「14 章实测阻断型 100% 是真缺陷 / 提示型 100% 是正当措辞」若无案例支撑即为空话。

### B2 的性质：不是伪造，是复制源错了

B1 与 B2 表面同类（例句不命中），**根因完全相反**：

- **B1 是凭印象写**——词根本不存在，改法是换成脚本产出
- **B2 是复制了但源被截断**——词是真的、句子是真的，**只是少了尾巴**

**分开记的原因**：B1 靠 `vocab_candidates.py` 根治；B2 靠「取原文完整子串」根治，
**两者用同一个禁令（1a）会漏掉 B2**。
判据：`grep -w <词头> text/chNN.txt` 有命中但例句仍不命中 → **B2 类，不是 B1**。

| FAIL | 14,866 | **5,238** | **−9,628 = 64.8% 是假红** |

复现：

```bash

git show HEAD~1:scripts/check_vocab.py > $S/before.py
# ⚠️ 必须带 PYTHONPATH，否则 import 不到 verify_quotes → 输出空白
PYTHONPATH=scripts python3 $S/before.py "<书目录>" | grep -E "^--- (FAIL|WARN)"
python3 scripts/check_vocab.py "<书目录>" | grep -E "^--- (FAIL|WARN)"
```

### F5 未修的原因：它是流程坑，不是工具坑

**空输出不是「0 FAIL」**——这是第 N 次「0 常来自工具坏掉」。
同源已犯过的三次：
1. 回归脚本把 `KeyError` 当成「0 条候选 0 缺陷」
2. symlink 相对路径导致 probe 假 FAIL
3. `grep` 对一句真实存在的英文引语报 0 次

**通用规约**（已并入 AGENTS 8.4「临时命令的输出同样不能当证据」）：
> 任何回归/探针脚本的输出，**先判 `Traceback` 与退出码，再读数字**。
> 空白与 0 是两件事，**先分清再解读**。

### 探针的第二个同源错误：重推 ≠ 复制

本次统计「`ch_corpus` 为空的文件数」时，我**自己重推了一套映射逻辑**，
得出 **8,336**；照抄工具的三级推导（`source_text` → 文件名 `chNN` → `chapter:`）后是 **1,568**。

**差 5 倍。** 根因与 §8.5 记录的第 3、4 次跨源归属错位同源：
**统计口径没锁死就报数**。

> **规约**：探针要**复制被测物的推导**，不是重新推导一遍。
> 复用 `check_vocab.load_chapter_corpora` / `OVERVIEW_RE`，不要自己写 glob。

## 四、这一轮的四条元教训

1. **「100% 是真缺陷」只在分类之后成立。** 14 章实测里阻断型 100% 真、提示型 100% 假，
   但**同一个数字在不分类时无法解读**——两类混在一起时，人先改提示型，或者整份忽略。
   分类不是为了好看，是为了让「改」这个动作有依据。

2. **假红的最大一块不是启发式粗糙，是「判定前提缺失却照样判」。**
   F1 占全库 FAIL 的 **64.8%**——一个 `if not ch_corpus` 守卫而已。
   **量级上，它比任何一条写作规则都值钱。**

3. **写规则时也会编造归属——而 grep 30 秒就能抓。**
   本库 P1 最初写的是「the-glass-girl ch07，我差点改掉三句没错的话」。
   `grep -rn "不改动一个字" notes/books/` 的结果是 **ch01 prologue.md:31，1 处**；
   再查 ch07 的**首次提交版**（`git show <首次提交>:<路径>`）——**从未有过**这类表述。
   **一次编造，两处落点（章号 + 数量）都是假的。**
   规约：**规则文档里凡出现「某书某章某处」，一律带 `grep` 复核过的行号**；
   写不出行号就别写章号。

4. **假红会连带制造「假回归」。** F1 修好后 WARN **涨了 1,166**——
   若不逐条核机制，就会把这 1,166 当成改坏而回滚，**顺便把 9,628 条假红放回去**。
   **报警数量变化本身必须归因，不能凭方向感判断好坏。**
