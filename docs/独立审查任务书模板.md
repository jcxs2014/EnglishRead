# 独立审查任务书模板

> **用途**：执行方完成一本书的精读（含自审）后，按本模板生成一份自包含的审查任务书，供独立审查方（另一实例 / 同机另一会话 / 用户指派的新会话）一键接手。
> **依据**：AGENTS.md 第 10 条「强制条款（2026-09-18 用户拍板）：两道审查」。
> **存放位置**：`docs/reviews/<slug>.md`（目录不存在则新建；本文件为空白模板，勿直接改）。
> **一句话启动指令（交给审查方）**：
> ```
> 请读取 docs/reviews/<slug>.md 与 docs/新书启动模板.md，按独立审查五步法审查《书名》，
> 输出缺陷清单（附文件+行号+证据），结论三档：通过 / 整改后通过 / 不通过。
> 目标书籍：notes/books/<category>/<slug>
> ```

---

## 任务书（执行方填空）

### 一、书籍信息

- **书名 / 作者**：
- **目录**：`notes/books/<category>/<slug>/`
- **epub 路径**：`notes/books/<category>/<slug>/library/<文件名>.epub`
- **体裁与格式**：（言情长篇 / 推理悬疑奇幻精简格式 / 随笔集 / 短篇合集 / 非虚构论述 / 诗歌回忆录）
- **体量**：章节数 ___ / md 文件数 ___ / 总览三篇（无总览的书须注明体裁是否为短篇合集）
- **章节映射说明**（如存在偏移/合并/跳过非正文页，逐条列明）：

### 二、执行方自审结果（第 1 道，必填，供审查方复验起点）

- **自审五步结论**：a ___ / b ___ / c ___ / d（缺陷数 ___，修复 commit ___）/ e ___
- **三件套原始数字**（粘贴原始输出，不许只写"X/X ✅"）：
  ```
  （verify_quotes 逐行输出）
  （check_chapter_quotes 逐行输出）
  （check_vocab FAIL/WARN 行）
  （check_entities 结果行）
  ```
- **短引语台账**（<20 flat 字符的引语逐条 grep 结果）：
- **已知偏差与豁免声明**（工具已知盲区造成的、人工确认过的项）：

### 三、审查方义务（第 2 道，不得打折）

1. **重跑门禁，不信自审数字**（AGENTS.md 第 10 条 a）：`verify_quotes` / `check_vocab` / `check_entities` / `check_chapter_quotes` 全部本机重跑；有总览的书加跑 `verify_overview_quotes`。
2. **五步法 a–e**：
   - a 三件套重跑
   - b 逐章归属（凡有 text/ 的书逐章跑 check_chapter_quotes，**特别检查 cliffhanger 跨章边界**——前一章悬念收尾、对话在后一章展开时，引语归属必须跟随对话实际发生章）
   - c 结构扫描（**行首引语块口径**：编号连续 / 子项齐全 / 零孤儿块 / 零重复块）
   - d 语义二审（引语↔分析逐对：中文理解/句子结构/关键词回查/说话人归属/数字断言；**子代理委派必须附 1–2 个本库真实失败案例 + 防幻觉条款**）
   - e 总览事实核对（人物身份/关系/结局/叙事结构交叉核对；总览引语逐字 grep + **说话人窗口核对**）
3. **四类高发坑位**（优先扫描）：总览层情节虚构（假恋情/假结局/假 POV/假双时间线）· 说话人反转（逐字命中≠说话人正确）· cliffhanger 跨章场景 · 跨书污染（陌生人名/地名先 `grep -rl "<name>" notes/books/`）。
4. **防幻觉条款**：报警前必须先 grep 确认引语行与所举报的分析行真实存在于同一 md 且相邻；禁止拿 text/ 句子与无关分析行拼装错位；查无实据的疑点标注"待人工复核"。

### 四、输出格式（审查方）

```
## 审查报告：《书名》
### a 门禁重跑（原始输出）
### b 逐章归属（全书逐章结果）
### c 结构扫描（编号/孤儿/重复块统计）
### d 语义二审（缺陷清单：文件 + 行号 + 引语摘录 + 分析摘录 + 原文 grep 证据 + 严重度）
### e 总览核对（引语 grep MISS 清单 + 事实错误清单）
### 结论：通过 / 整改后通过 / 不通过（附理由）
```

**报告去向**：① 写入 `docs/reviews/<slug>.md` 的"审查方报告"节；② 在 COLLABORATION.md 回帖（含结论 + 缺陷数 + 执行方需修的 commit 范围）；③ 通知用户。

### 五、边界与禁止事项

- 审查方**只报告、不修改**精读文件（AGENTS.md 第 7 条任务边界）；修复由执行方完成。
- 审查方的编号（①⑩ 等）是自编号，**不对应文件章节号**——执行方定位缺陷须回文件 grep，禁止套用编号映射。
- 执行方收到报告后**不得照抄结论即改**：须回原文 grep 整句确认（报告可能只指出表象，实际缺陷更深）。
- 疑似工具盲区（短引语、格式变体、省略号拼接）须人工 grep 复核后再定性，禁止直接判缺陷。

### 六、执行方收尾（审查通过后）

- 修复清单 + 修复 commit 追加进本任务书；
- COLLABORATION.md 补发"审查通过"回执（审查方身份 / 报告位置 / 修复 commit 清单）；
- 至此方可对外称"完工"（push 仍等用户指令）。
