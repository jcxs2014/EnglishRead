> **性质**：讨论稿，**未实施**。本文只做「问题取证 → 根因 → 提案 → 取舍」，不改动任何脚本或规则文件。
> **问题来源**：用户 2026-09-26 提问——「针对日志里面记录的问题，看看有没有可能对规则进行优化，尽量保证书籍在执行层面就可以避免问题，而不是依赖五步审查发现问题」。
> **取证范围**：`AGENTS.md`（345 行）、`docs/新书启动模板.md`（433 行）、`scripts/` 7 个主门禁脚本（**口径区分**：现存主门禁 7 个；P1 提案提升的是 9 个，含 2 个新脚本）、`.memory/daily/2026-09-22`～`09-26` 五天日志（2264 行，覆盖 30+ 本书）。
> **复现方式**：所有"实测"结论均在 `/tmp` 用最小样例当场跑过主门禁脚本，未改动仓库任何文件。
> **落地时需同步的规则文件**：`AGENTS.md`（执行规则）、`docs/新书启动模板.md`（开工入口 + 门禁时序表）、`.memory/AGENTS.md`（记忆索引，仅在新增脚本时补一行）。

## 一、结论先行

近 5 日审查抓到的缺陷中，**机械可判定部分约占 55–60%**——这部分本可以在「每章写完即跑」的机械检查里拦下，不必等五步审查。

**⚠️ 但在这一切之上还有一层更靠前的盲区（2026-09-26 §10.1 补入，优先级最高）**：本方案 §三 的六项实测**全部以 `text/` 为真值**。若 `text/` 本身整体错误（最典型：extract 边界错误把两篇合并进一个文件），则 `check_chapter_quotes` / 全串 sweep / 关键词锚定 / 例句核验**全部垃圾进垃圾出**——Open Secrets 实证：`check_chapter_quotes` 79/79 全绿、`verify_quotes` 全绿、`audit_book.py` A2 也拦不住，因为引语**确实**在「那一章」的 text 里（两个故事都在）。**故本方案新增 P0-0：语料层验收。**

三类根因（不是"规则不够多"）：

1. **检查器散在 `scripts/attic/`（gitignored，112 个 .py），每本书重建**——同一功能平均 3–6 份实现，口径各不相同，写作期无"标准检查器"可调。
2. **内联 Gate（AGENTS 第 8 条）只点名 4 个主门禁，而这 4 个的口径都是"前缀 / 子串 / 词频"**——结构、锚定、全串、数字台账、章节标签一条都不在内。
3. **缺一条"先取证、后落笔"的硬顺序**——先写分析再回填引语 / 先写词表再回头验证 / 凭印象写总览，三个根因在日志里都已被点名。

真正**不可**执行期预防的只有语义层（说话人、人物关系、情节断言、语法术语判定），这正是五步审查 d 步不可替代的边界。

## 三、实测复现的执行层盲区（最硬的证据）

以下 5 项均在 `/tmp` 用最小样例当场跑主门禁脚本复现，非推测。

### 3.1 52 字符指纹盲区

构造引语，尾部接原文不存在的右段：

```
> **原句 1:** "...gone forever and nobody remembered it at all… and a room within the room"
```

`verify_quotes` 报 `1/1 ✅`，exit 0。右段（`and a room within the room`）在 epub 中查无。

把 `remembered` 改成 `rememberedX`（差异在第 52 字符之后）→ 同样 `1/1 ✅`。

**成因**：`verify_quotes.py` 第 116 行 `frag = qa[:52]`；`check_chapter_quotes.py` 第 139 行 `fq[:60]`。
**实证背景**：AGENTS 第 10 条 d 步已把它列为"终验标准件：整行连续 sweep"，但**只写进了审查要求，没写进写作期 Gate**。

### 3.2 子串判定导致"首词被吞"放行

```
md   : "Hate it here. Will you take me away with you"
原文 : "I hate it here. Will you take me away with you"
```

- `verify_quotes` → `1/1 ✅`
- `check_chapter_quotes` → `1/1 in ch01 text` ✅

两者都判 flat 后的**子串**存在，而真实缺陷是引语首词被吞。
**实证背景**：Forgotten Sisters 批次为此专门写了 `attic/audit_bounds.py`（v3 才收敛到 0 误报），该脚本至今在 `attic/`。

### 3.3 `check_vocab` 对 4 列表格完全不看例句

`check_vocab.py` 第 176 行：`entry, meaning, example = (cells + ['', ''])[:3]`

同一句虚构例句：

| 表格格式 | 结果 |
|---|---|
| 3 列（词 \| 释义 \| 例句） | ❌ FAIL（正确拦截） |
| 4 列（词 \| 词性 \| 释义 \| 例句） | ✅ **FAIL 0（漏网）** |

**表头实测分布**（2026-09-26 复核）：4 列表头第 2 列为「音标」615 行、「词性」569 行——**两类最后一列都是「例句」**，故"取最后一列"方向正确。

**影响面（2026-09-26 更正）**：全库 **26 本书、1184 行** 4 列词汇数据行的例句从未被校验，而 AGENTS 第 5 条要求"例句须出自原文"。

> ⚠️ **本节数字更正**：初稿写"6936 行"。复核发现该数字来自有缺陷的统计脚本——它把词汇表里**所有 ≥4 单元格的行**都计入，其中 5773 行根本不是例句行（音标/词性列表等）。按"4 列且最后一列标为例句"重算：表头 1187 行、数据行 **1184 行**，26 本书不变。书的数量与 bug 机制不变，影响面比初稿小近 6 倍。
> **教训**：统计口径没锁死就报数——正是 §8.2「跨书数据串位」的同源问题，本方案自己犯了一次。取证命令见附录。
**实证背景**：Misery's Wife 批次（09-23）已独立发现同一 bug 并记录在案，但工具侧未修。

**顺带查出两个活的仓库问题**（不在本方案范围，建议单独立项）：

1. **10 行 4 列数据行的最后一列不是例句**，而是短词或标注：
   ```
   ch07 Chapter Seven.md | graft | (未出现，仅记忆)     ← AGENTS 明令禁止的绕过标注
   ch43 … | dad | Dad?      ch53 … | baby | Our baby.
   ch47 … | dad | My dad.   ch50 … | prescription | New meds.
   ```
2. **全库仍有 282 处「（未出现在原文）」标注**（`the-lost-village-by-camilla-sten` 一本 7 处）——AGENTS 第 5 条与 Barron's 教训点名禁止的绕过写法，至今未清干净。

### 3.4 「0 提取」= 假绿

某文件的引语格式不被解析时，`verify_quotes` / `verify_overview_quotes` 打印 `⚠️ 未提取到编号引语` 后 `continue`——**不计入分母**。只要别的文件有引语，总账照样 `1/1 100%`、exit 0。

后果：言情 `> "..."` 格式、`<原句 N>` 变体、bullet 列表引文等**只要有任意一个文件被漏解析，整本书就是绿的**。

### 3.5 缺整节不报

一章完全没有 `## 词汇分级`，`check_vocab` 词条行不计数、FAIL=0。

**实证背景**：Such a Fun Age 批次 25/28 章缺「本章词汇」+「一句话总结」，四件套全绿，**靠审查期结构扫描才发现**。

### 3.6 全库盘点：P0-1 的真实影响面（2026-09-26 新增）

对 354 个书目录跑 `extract_quotes()`，统计「长引语 0 条 且 短引语 0 条」的文件，再按文件名角色分派：

| 类别 | 文件数 | P0-1 该如何处理 | 性质 |
|---|---|---|---|
| 非内容文件（审查报告 / HANDOFF / index / COLLABORATION） | **6** | **从扫描中排除** | 本就不该扫 |
| 概述类（概述 / overview / 00_全书概述） | **209** | **允许 0**——概述按设计是散文，无编号引语 | 正常状态 |
| 金句 / 节点类（金句精选 / quotes / 情感节点 / emotional） | **213**（涉 160 本书） | **0 = FAIL** | 真盲区 |
| 正文章节 | **168**（涉 22 本书） | **0 = FAIL** | 真盲区 |

**结论**：P0-1 不能写成"0 提取 = 失败"的二元判断，必须**按文件角色分派**。真红规模是 **381 个文件 / 约 180 本书**。

**判定链已逐文件验证（2026-09-26 复核，防"分类本身造假绿"）**：判定顺序为 `非内容 → 概述 → 金句/节点 → 正文`，逐个正则命中实测：

| 文件名 | 概述正则 | 金句正则 | 落点 |
|---|---|---|---|
| `00 情感节点.md` | ✗（文件名不含"概述"） | ✓ | 金句/节点类（应红） |
| `00_金句精选.md` | ✗ | ✓ | 金句/节点类（应红） |
| `00 概述.md` | ✓ | ✗ | 概述类（允许 0） |
| `00_全书概述.md` | ✓ | ✗ | 概述类（允许 0） |
| `ch03 chapter one.md` | ✗ | ✗ | 正文章节（应红） |

**全库「被误判进概述类的金句/节点文件」实测 = 0 个**。即 `00 情感节点.md` 不会因 `00_` 前缀或"先判概述"而落入允许 0 的类别——这是本节数字可信的前提。

> **复核记录**：另一 agent 曾提出"分类顺序把 `00 情感节点.md` / `00_金句精选.md` 归进了概述类，会低估真盲区"，经上述逐文件验证**不成立**——该两文件名不含"概述"，`elif` 链正确落到金句/节点分支。旁证：其自身复算所得 213 / 209 与本节完全一致；若确有误路由，概述数必偏高、金句节点数必偏低，两数不可能同时对上。

**这也解释了一个长期被误读的现象**：每本书的完工通报都写「`00 概述.md`: ⚠️ 未提取到编号引语」——那是**正常状态**，不是缺陷。真正的信号是 213 个金句/节点文件抽不出编号引语，说明**总览层引语从未被门禁看见过**。

正文章节 0 提取的 22 本书集中在几类：`dreamland`（多章）、`heir-of-prophecy`（ch11–ch57 大段）、`green-city-wars`（ch08–ch24）、`everything-was-beautiful`（ch05–ch22）、`barron-collected-short-fiction`（多篇）、`Very Short Stories by Sean Hill`（全部 7 篇，文件名为主题而非引语格式）。

> **实施要求**：改 P0-1 之前先跑一次全库盘点，产出这四类的清单作为待修队列。**新书直接按分派卡住；存量书先出清单再分批修**——否则这条改动会在第一天制造混乱（分不清是工具错了还是书错了）。

## 四、根因分析

### 4.1 检查器散在 `attic/`，每本书重建（最贵的一笔重复劳动）

`scripts/attic/` 共 **112 个 .py**（目录被 `.gitignore` 第 125 行忽略）。按功能归类：

| 功能族 | 实现数 | 代表 |
|---|---|---|

| 词汇双向 | 10 | `check_vocab_bothways` / `check_vocab_head` / `scrub_vocab` / `strip_placeholders` |
| 结构扫描 | 9 | `audit_struct` / `selfcheck` / `structure_scan` / `struct_audit_c_step` |
| 关键词锚定 | 8 | `check_anchoring` / `keyword_anchor` / `kw_anchor_{am,df,ksr,afs}` |
| xref | 8 | `audit_xref` / `fix_overview_refs{,2,3,4}` |
| 全串 sweep | 6 | `sweep_chapter_quotes` / `verbatim_sweep` / `tokseq_b_step` |
| 短引语台账 | 3 | `check_short_quotes` / `short_quotes` / `verify_short_quotes` |
| 计数断言 | 3 | `count_claim_audit` / `count_claims` / `fix_count_claims` |
| 引语边界 | 3 | `audit_bounds` / `fix_bounds_defects` / `fix_quote_level` |
| 语义/说话人 | 3 | `audit_sem` / `chapref_check` / `semantic_crosscheck` |
| 损坏扫描 | 2 | `corruption_scan` / `fix_mojibake` |

**后果**：① 写作期没有标准检查器可调，这些检查要么不做、要么留到审查期现写；② 同一功能 3–6 份实现，**执行期与审查期口径不一致**——审查期换一个口径跑出不同数字，等于"用不同尺子量两次"。

> **⚠️ 同规模的隐藏成本（2026-09-26 §10.1 补入）**：本节与 §9.1 盘点的都是"审查期现写**检查器**"，但**写作期现写「提取器」是同规模甚至更大的成本**——短篇集几乎每本都要现写拆分器（`split_murdoch_letters` / `extract_morningside` / `extract_progress_of_love_text` / `extract_pictures_of_you_text`…），且**提取输出质量决定全部下游门禁的真值**。一次边界错误（两篇合并进一个文件）会让 `check_chapter_quotes` 79/79 全绿——因为引语确实在"那一章"的 text 里。**故语料层验收提为 P0-0。**

### 4.2 内联 Gate 只覆盖 4 个"前缀型"门禁

AGENTS 第 8 条（每章写完即跑）只点名 `verify_quotes` + `check_vocab`（d 项），8e 把关键词锚定检查器写成"**≥20 章推荐**"——等于可选。

而这 4 个主门禁的口径都是**前缀 / 子串 / 词频**：结构、锚定、全串、数字台账、章节标签**一条都不在内**。

### 4.3 缺"先取证、后落笔"的硬顺序

日志里三个根因已被明确点名：

| 根因 | 实证 |
|---|---|
| 先写中文理解、后挑引语 → 引语截短 | Such a Fun Age 18 处系统性截短，根因写明"先写中文理解、后引用语时引语被截断" |
| 先写词表、再回头验证 → A 类虚构 | Down Girl 120+ 处 / Why We Die 50+ 处 / Exhausted / AOY ~20 处 |
| 凭对 text/ 的印象复述情节 → 总览虚构 | The Morningside 概述 4 处（1 完整虚构引语 + 1 整段虚构情节 + 1 漏前半句 + 2 自造改写） |

**反面证据同样明确**（说明纪律有效，不必换工具）：

- Down Girl：改用「脚本抽候选 → 逐条双重校验 → 只写通过者」的机械流程后，累计拦截 120+ 处，最终 0 缺陷；
- Such a Fun Age：`vocab_pick.py` + 8 个 `vfy*.py` 按 `check_vocab` 的 flat 口径**预验证**再写入，292 条一次通过；
- Eye of Leviathan：「引语占位符注入法」（从已写好的章节 md 提取第 k 条原句）使总览引语逐字 + 章标双正确，情感节点 26/26 一次通过；
- China's World View：子代理按"先 grep 筛词再写表"执行，7 章一次通过 0 FAIL；主会话按相反顺序写的 11 章被内联 Gate 拦下约 55 处。

### P2-5｜报警处置台账 `gate_log.md`

机械检查变多之后，**报警的处置状态本身需要一个台账**。否则会出现「报了 200 条、修完不知道哪些没修、下一批又重报」。

- **落点**：书目录内 `gate_log.md`；字段建议 = 日期 / 工具 / 报警摘要 / 处置（已修·误报·人工兜底·待办）/ 复核方式。

## 九、审查瘦身：执行期前移能省下多少（2026-09-26 用户提问）

> **问题**：五步审查耗时太多。如果执行期就规避大量问题，审查阶段能否减少步骤？
> **回答**：能减，但减掉的是**「发现成本」**，不是**「核验成本」**。而且最大的时间黑洞其实不在五步本身，而在「审查期现写检查器」。

### 9.1 先纠正一个直觉：审查时间最贵的一块不在五步里

| 耗时来源 | 量级 | 可压缩性 |
|---|---|---|
| **审查期现写检查器** | 每书 6–7 个（AOY 6 个 · Forgotten Sisters 7 个 · Lace 6 个）——这正是 `attic/` 112 个 .py 的来源 | **可归零**（前提是 P1 落地） |
| **d 步子代理批次** | 3–5 批，受 ~200k 字符载荷上限约束（15 个 md 触顶 `AGGREGATE_CONTENT_TOO_LARGE`），含超时重派 | 机械层预清后才缩小 |
| **报警复核** | 驳回率 15–21%（Dominion 11/53 · Lace II 5/33 · Impossible Garden 12/~100 · Floating Hotel 3/76），每条都要主会话 grep 复验 | 随报警纯度上升而下降 |
| **短引语人工兜底** | 每书 15–59 条逐条 grep（That First Flight 40 · Worlds Collide 59 · Such a Fun Age 27 · HBR 40） | **可自动化**（P1 `check_short_quotes`） |
| a/b/c 三件套重跑 | 本身很便宜 | 便宜但**不能删** |

> **关键判断**：第一、三、四项是**纯机械成本**，P1 落地后可直接归零或大幅压缩。第二项（子代理）只有在机械层预清后才会缩小——这是全部收益的杠杆点。

### 9.2 逐步骤的可减性

#### a｜三件套重跑 — 不可删，但从「第二次发现」降为「完整性确认」

- **不能删的理由**：它是反自欺机制（NS 报 101/101 实为 108/109 含 1 FAIL；修复报告 2/3 与现场不符；Tinder Box 3 章跨章错植 + 6 条金句虚构）。删了它，整套门禁就失去意义。
- **但漂移的根因是口径不一致**：写作期用主脚本（前缀指纹），审查期用 `attic/` 脚本（全串 flat），两边数字必然不同——重跑于是退化成「用第二把尺子再量一遍」。
- **前移后**：同脚本、同口径 → 重跑回到 30 秒的完整性确认。
- **附带收益**：P0-1 修掉「0 提取假绿」后，「20/20 干净」这句话**第一次有意义**——现在这个 20 可能是漏解析换来的。

#### b｜逐章归属 — 机械部分归零，cliffhanger 语义部分保留

- `check_chapter_quotes` 本身很便宜（全书扫描秒级）。
- 真正贵的是 AGENTS 第 9e / 第 10b 要求的「**cliffhanger 跨章边界须同时读前后章 text/ 各 ~100 行确认**」——那是语义判断，**留在审查期**。
- 前移后：全串 sweep 每章跑，机械归属写完即定；审查期只处理 sweep 报警的少数条目 + cliffhanger 抽查。

#### c｜结构扫描 — 最容易被误判为「可删」的一步，但**不能删**

实测反证：**How Much of These Hills 的 d 步批量修复脚本误删了 c 步刚插入的 32 条「读者视角提示」**（HEAD diff 51 删/19 增），从 `1fdbfcd7` 按块还原才修复。

- **c 的价值已经转移**：从「发现写作期结构缺陷」→「**验证审查期自己的修复没破坏结构**」。
- **新定位（三次）**：写作期跑（发现）→ 审查期修复前跑一次（基线）→ 修复后再跑一次（防自伤）。
- 与 AGENTS 第 9g（禁 `re.S` 跨块）、第 10 条 c 步配套使用。

#### d｜语义二审 — 核心不可减，但载荷可大幅缩小

| 子项 | 归属 |
|---|---|
| 引语全串 / 词汇例句 / 跨章引用 / 分析层行内英文 / 计数断言 / 关键词锚定 | **前移**，d 步不再承担 |
| 说话人 / 人物关系 / 情节断言 / 语法术语判定 / 译法 | **完全不可减** |

机械占比各书差异很大（从缺陷清单反推）：

| 书 | 缺陷总数 | 其中机械可判定 | 占比 |
|---|---|---|---|
| Floating Hotel | 48 | 7（引语 4 + 结构 3） | ~15% |
| Why We Die | 62 | 12 | ~19% |
| Forgotten Sisters | 166 | ~79 | ~48% |
| Exhausted | 63 | ~35 | ~55% |
| China's World View | 132 | ~78 | ~59% |
| Lace | 89 | 76 | ~85% |

> **均值约 55–60%**（口径限制见 §9.6）。

**真正的收益不是时间，是假阳性率。** 子代理现在的任务书要求它同时判两件事：

1. 「引语是否逐字」——**它判不准，这本该脚本干**；
2. 「分析是否正确」——这才是它的能力范围。

前移后任务书只留第 2 项，报警纯度上升 → 主会话复核成本跟着降。这解释了为什么多本书的审查都出现「报警 N 条 → 驳回 M 条」的固定开销（Dominion 11/53、Lace II 5/33）。

#### e｜总览层 — 可拆两半

| 侧 | 内容 | 归属 |
|---|---|---|
| 机械侧 | 引语逐字（P0-1）· 章节标签对账（P1）· 行内英文（P1）· H1 语义（一行 grep） | **前移** |
| 语义侧 | 人物身份/关系/结局走向 · 说话人 ±200 字符窗口 · 情节断言 | **保留** |

The Morningside 的 e 步正好示范这个分界：章节标签错可脚本化；说话人误归不可（金句⑱ `That's not like her.` 上下文写成「母亲拒绝帮女儿开门」，实为 ch22 董事会 Mrs. Gaspard 怀疑 Bezi Duras 主动认领筹办——引语逐字为真，`verify_overview_quotes` 27/27 全绿照样漏网）。

### 9.3 一条机制缺口：换检查路径应该「设计出来」，不是「临时现写」

AGENTS 第 10 条要求审查方「换检查路径、不采信写作期数字」。但**现在「换路径」的实际含义是每本书现写一个新脚本**——这既是审查时间的大头，也是口径漂移的根源。

**改造思路：每个机械层配两套实现，写作期一套、审查期一套，路径天然不同。**

> **⚠️ 本节拆两阶段（2026-09-26 交叉审阅后修订）**。原稿把两套实现并列提出，但其中两行并不成立：
> - 结构层写的是"第二份独立实现（**或换口径重跑**）"——这是未决选项，不是方案；
> - 分析层行内英文层要"不设 ≥3 词门槛，全量扫"——**门槛撤掉后误报率会跳多少，没有数据**。
>
> **因此拆为两阶段**：**第一阶段只做写作期那一套（P1 的 9 个）**；审查期"换检查路径"暂时靠**换人或换子代理**承担（§8.3 本来就规定两者不能合并）。等审查期脚本的需求被 2–3 本书真实使用验证过，再决定要不要建第二套。
> **理由**：避免造出一堆"理论上换路径、实际上没人调"的脚本——`attic/` 112 个 .py 里已有相当一部分属于这一类。

| 层 | 写作期（第一阶段：P1 的 9 个） | 审查期（**第二阶段，暂缓**） |
|---|---|---|
| 引语 | `verify_quotes` 前缀指纹（`qa[:52]`） | `verbatim_sweep` **byte-exact 逐字**（不 flat 化，保留标点与撇号形态） |
| 逐章 | `check_chapter_quotes` 前缀（`fq[:60]`） | `sweep_full` 全串 flat + fragment 分段取证 |
| 词汇 | `check_vocab` 词头 + 例句**前 60 字符** | `check_vocab_bothways` 例句**全串 flat** + 词头词边界 |
| 结构 | `audit_structure` | 待定——需先确定"换口径重跑"具体指什么 |
| 分析层行内英文 | `sweep_analysis_inline`（≥3 词门槛） | 待定——门槛是否撤掉需先测误报率 |

**效果（仅第一阶段可达）**：「换路径」从**每书一次的创造活动**降为**换人或换子代理**，写作期不再需要现写检查器。第二阶段的完整目标——「换路径」变成一次性架构工作——**待验证后再定**。

> **与 §八.3 边界原则的兼容**：两套实现都是「取证」，不是「复核」。AGENTS 第 10 条要求的**换人 / 换子代理 / 异实例复核**仍必须保留——两套脚本都是自己写的，不能替代换一个无写作上下文的读者。

### 9.4 一个反直觉的红利：缺陷数决定修复批次大小，修复批次大小决定自造损坏

全库所有「脚本化批量改写损毁」事故都发生在大修复批次上：

| 事故 | 批次规模 | 后果 |
|---|---|---|
| Lace 独立抽样复核 | 首轮整改 89 处 | 修复脚本**自造 2 处损坏**（重复从句 + `。。` 拼接） |
| All Our Yesterdays | 130 个改动单位 | 3 处 U+FFFD 字符损坏 |
| How Much of These Hills | d 步批量修复 | **误删 c 步刚加的 32 条**「读者视角提示」 |
| Memories Like Fangs | `re.S` 跨块 sub | 损毁全书 **116 处**结构 |
| Daggerbound | 批量改写 | 71 处异常 |

> **结论**：前移的收益不只是省时间，是**把修复批次变小**，从而降低「修复动作本身成为缺陷源」的概率。这是审查瘦身之外的额外红利，也是 P0/P1 除「省时间」之外的第二条收益论证。

### 9.5 审查瘦身后的形态（提议）

| 层 | 内容 | 定位 |
|---|---|---|
| **Tier 1 完整性**（机械） | a 三件套（同脚本同口径）+ 结构复扫 + corruption_scan（防修复自伤，§10.3）+ 全串 sweep / 词条例句全串 / 章节标签对账（用审查期第二套实现）+ 短引语台账 | 从「每书重新发明检查器 + 全量扫」变成「跑两套现成脚本」；**仍是必跑，不可省** |
| **Tier 2 语义**（判断） | d 语义（引语↔分析对应、说话人、事实、语法、译法）+ e 语义（身份 / 关系 / 结局、情节断言） | 送审范围从**全书全量**收窄到**机械层放行后的剩余块** |

**对应到 AGENTS 第 10 条的表述建议**（若采纳）：

- a、b、c **保留**，但重新定位为「**完整性 + 防自伤**」而非「发现」；
- d 步的机械子项（整串 sweep / 关键词锚定 / crossref / 数字回算）标注为「**写作期已跑，审查期只跑第二套实现做交叉验证**」；
- d、e 的语义子项**不缩减任何一项**；子代理任务书可**删去**「逐字核对」要求（已由脚本保证），只保留语义判断——任务书更短、更聚焦、误报更少。

### 9.6 诚实声明

1. **55–60% 是从缺陷清单反推的比例，不是实测时间占比。** 本项目不记录每步耗时，真实时间分布**没有数据**。
2. **要给出可靠的时间节省估算，需做一次 A/B**：同一本书按现状审查 vs 按新流程审查，记时。成本不高（一次审查的时间），但本方案**未做过**，因此不给出具体小时数或百分比。
3. **§9.3 的双实现会增加脚本数量**（机械层从 9 个增至约 14 个），这是 §七 拍板项 2 的成本侧，需一并权衡。
4. **Tier 1 不可省。** 本节所有「瘦身」指的是**定位转变**（发现 → 完整性确认），不是**步骤删除**。若把 a/b/c 当作可省步骤删掉，会同时失去反自欺与防自伤两道机制——这正是 §八.3 那条边界原则要防的事。

### 10.1 语料层（text/）验收是全部门禁的真值前提——方案最大的未覆盖盲区 → **已提为 P0-0**

**实证**（`.memory/daily/2026-09-24.md:256-267`）：Open Secrets 的 extract 边界错误把 **Carried Away（Louisa/Jack Agnew）并入 ch01**（138KB）、**Vandals（Liza/Ladner/Warren）并入 ch06**（123KB）。后果链：

- `check_chapter_quotes` 79/79 全绿——引语确实在"那一章"的 text/ 里，因为**两个故事都在里面**；
- `verify_quotes` 对 epub 全文匹配也绿——内容确实都在 epub 里；
- `audit_book.py` A2 节（"逐章取多点指纹回查 epub，防语料污染"，`audit_book.py:74-97`）同样拦不住——**它防的是"内容保真"，不防"归属边界"；合并场景下内容与 epub 逐字一致**。

即：**方案 §三 的六项实测全部以"text/ 为真值"展开，而 text/ 本身可能整体错误，所有以它为基准的门禁（check_chapter_quotes、sweep、锚定、例句核验）会垃圾进垃圾出。** 修复靠的是人物锚点 grep——"每文件只应含本篇人物、不应含相邻篇人物"。

同类前例：Living on Paper——epub 导航把 Part Four/Six 错标为 "Plate 1/2"（实为 148k/239k 正文），按内容重命名（09-25.md:203）；短篇集几乎每本都要现写拆分器（`split_murdoch_letters` / `extract_morningside` / `extract_progress_of_love_text`…）——§9.1 只盘点了"审查期现写检查器"，**写作期现写提取器是同规模的隐藏成本，且提取输出质量决定全部下游门禁的真值**。

**提案**：P1 增补第 8 个脚本 `verify_corpus.py`（或并入开工第 1 步强制 Gate）：
1. 件数 = 预期篇目数（已有条款，但预期数从哪来见 10.2）；
2. **人物锚点双向 grep**：每件 grep 本篇人物（应 >0）+ 相邻篇人物（应 =0）；短篇集/分部书/多 POV 书必跑；
3. 每件打印首句/末句人工过目（抓"从句中间开始/句中间结束"的边界错位）；
4. 可选：双提取 diff（attic 已有 `diff_extractions.py`，09-25.md:17 曾用它排除"提取器篡改"误判）。

> **⚠️ 实施约束（2026-09-26 补入，经交叉审阅）**：第 2 项的**反向锚点（"相邻篇人物应 =0"）必须使用该篇独有的实体**——全名 + 独特称谓 + 该篇独有的地点/物件/意象，**不得用"任一出现过的名字"**。短篇集里两篇共享同名角色时（如多篇都用 `Sarah` / `the mother`），用泛名会假红，用该篇独有实体才有效。
> **根因与 §3.3 那次自查同源**：**校验规则本身也会造假绿**——规则写得对不等于跑出来对。故本脚本启用前必须先在**已知良好的书**上跑对照（§六.1 规矩），且反向锚点清单须人工确认"该实体确属本篇独有"。

### 10.2 篇目对不上时先怀疑合并，不要单方宣布"精选本"；"清单发用户确认"在修复会话里最易被跳过

**实证**：Open Secrets 第一轮修复中，本实例扫描 bullet 只定位出 6 篇，搜 "Carried Away"/"Vandals" 只命中版权页，据此**单方宣布"epub 为 6 篇精选本，版权页列表是发表出处不是收录篇目"**——结论错误，两篇实际都在书里（被合并进邻居）。用户派单以 split 级证据纠正。

**教训**：① 版权页发表出处列表 + 目录页 + bullet 实测三方不一致时，**差异方向先按"合并/拆分错误"排查**（去邻居文件里找缺失篇目的特征人物/意象），排除后才可下"缺篇"结论；② 模板第 1 条"章节清单发用户确认"——本次事故发生在修复会话，开工对齐步骤被整段跳过。**修复/续接会话与新书会话同等适用第 1 条对齐**，这点建议写进模板第 0 条。

### 10.3 P1 名单缺 corruption_scan（第 8 个脚本的另一个候选）

> **归属更正（2026-09-26 复核）**：本条原稿写"Happiness Blueprint 批次…（09-25.md:28）"。经 awk 核验，**第 28 行属于《Lace》**（该书起始于第 3 行，下一节始于第 33 行）；Happiness Blueprint 的记录在 `09-24.md:243`。**结论不变（`corruption_scan` 该进 P1），只是它引用的证据本方案 §9.4 已有。**

### 10.4 P0-4 只查"缺节"，不查"垃圾节"——Morningside 词表崩坏是它的漏网变体

**实证**（09-26.md:71）：词表节**存在**但内容是数百行 `xxx —— 未见于原文` 重复占位（ch24/25/28/30/31 各一次），check_vocab 拦不住（无词条可 FAIL），靠占位行 grep 发现。同类：`| 词 | — |` 占位行约 40 行（AOY，09-25.md:1031）、`—— 本章无此搭配` 空壳行（09-25.md:1155）。

**提案**：把"**占位/垃圾行扫描**"加进 P0-4 或 P1 audit_structure 职能：`未见于原文`、`本章无此搭配`、`（未出现`、行尾 `\| *$`、单独 `—` 单元格、重复 ≥3 次的相同中文短语。attic 的 `scrub_vocab` / `strip_placeholders` 是干这个的——提升时把"扫描"（门禁）与"清除"（写操作）分开。

### 10.5 audit_structure 必须按体裁分派，否则重蹈 audit_book.py C 节误报

**实证**：AGENTS 盲区表明载 audit_book "C 节五子项对言情/精简格式四子项误报"；多本书完工通报写"C 节缺概览节是短篇合集格式已知误报，未据此改动"。这是 WARN 疲劳的既成来源（§六.2）。若 P1 的 audit_structure 不做体裁分派，会把同样的事再犯一遍。

**分派维度**（实施时写死成表）：① 子项数（言情/精简=四子项；期刊/短篇=五子项；诗歌回忆录=五子项+诗歌技法专项）；② 每章引语配额（言情/精简 3–8；短篇/期刊 10）；③ 必备节名按格式各有一套；④ **总览豁免 = 短篇合集**。

**同书内格式漂移也要容忍**——本实例 Open Secrets 实测：同书 8 个文件里 `**原句N:**`（无空格）与 `**原句 N:**` 并存、`**中文理解：**`（冒号在星号内）与 `**中文理解**：`（冒号在星号外）并存，首次结构扫描误报 2 文件 ❌。扫描器两种口径都认（是否反向"归一化 md"另议）。

7. **⚠️ 边界注记一｜两个工具的 `flat` 实现不一致（latent，实测影响面 0）**：

   | 项 | verify 侧 | chapter_quotes 侧 |
   |---|---|---|
   | `choice\n to stay` | `choicetostay` | `choicentostay` |
   | `\nabla` / `\neq` / `\theta` / `\to` | `abla` / `eq` / `heta` / `o` | `nabla` / `neq` / `theta` / `to` |

   - **跨工具不对称**：若 md 侧把字面量归一化成真换行，verify 命中而 **check_chapter_quotes 假 MISS**。

   - **实测影响面 = 0**：全库 `text/*.txt` 含字面 `\n` 或 `\t` 的文件数为 **0**。

   → **不设 P0-8**（无当前危害）。改为在 **P0-0 语料验收**加一条零成本体检：「提取件是否含字面 `\n` / `\t` / LaTeX 命令」——有则该书走人工比对而非纯脚本 flat。理由：现在动 `flat_alpha` 风险大于收益（改后全书 flat 变化会连锁影响 `check_vocab`），**先设检出闸，不动刀**。

8. **⚠️ 边界注记二｜逐行 `text/` 会让 byte-exact 层必然假 MISS**：
   诗歌回忆录类（`ten-bridges-ive-burnt` 实测 ch01 = 393 行 / 3317 字节 ≈ 8 字节一行）的 `text/` 是**一句一行**，任何跨行摘录在 byte-exact / 行级比对下必然 MISS（表现为 `15` vs `15\n` 差一个换行）。**这是格式差异，不是引语虚构**——flat 层不受影响（`flat` 本身会剥换行）。
   → 凡用 `verbatim_sweep` 一类**不做 flat 化**的层（§9.3 审查期第二套），须先判定该书是否逐行提取；若是，只作提示不判缺陷。与 AGENTS 已知盲区表「多行诗歌系统性 MISS」（Icosiel / Manca 韵文）同源。

## 十二、第五轮复核：两个新盲区（2026-09-26 追加）

> 来源：本实例对 §三 六项实测的独立复核。**两项均当场跑过脚本，不属于论证。**
> 其中一项在复核过程中先被我自己的初版测试判成"大面积盲区"，经逐条回源后**证伪并撤回**——撤回过程一并留痕（§12.3），因为它与 §8.6 记录的"统计口径没锁死就报数"是同一类错误，且这次是我自己犯的。

### 12.1 「可迁移表达」层完全在门禁之外（方案未覆盖）

**实证**（`notes/books/`，2026-09-26 实测）：

| 项 | 数 |
|---|---|
| 含「可迁移表达」节的文件 | **200**（正文章节 197 + 总览 3） |
| 涉书 | **12 本**（其中 8 本表格形态 · 4 本裸列表形态） |
| 形态 | 表格 `\| 表达 \| 含义 \| 可迁移场景 \|` 191 文件 / 裸圈数字列表 9 文件 |
| **被 `check_vocab` 计入"词条行"的文件/行数** | **191 文件 / 846 行 / 8 本书**（Ten Bridges 400 · Empty Bottles 190 · book-lovers 99 · O Henry Prize 59 · HBR 54 · If You See Me 33 · Morningside 6 · Cabin Fever 5） |

**为什么现有提案拦不住**——两层都漏：

1. **逐字层漏**：`sweep_analysis_inline.py`（P1 新增第 4 个）与 `check_overview_full.py` 的扫描对象是「引语块 + 分析层行内英文片段」。可迁移表达表**既不在引语块格式内，也不在正文分析行内**——它是独立的 `##` 节、独立表头、独立表格。§8.1 把它归入"分析层行内英文"是**归类错误**。
2. **逐字层漏的原因**：`extract_quotes()` 对表格行与裸列表行**均抽 0 条**（当场实测）——即它连"引语候选"都不算：

   ```
   表格行   '| **rage smells like nostalgia** | 愤怒闻起来像怀旧 | 描述"中年愤怒" |'  → 长引语 0 / 短 0
   裸圈数字 '**①** Some days it astonishes me how much effort it takes to be alive.'      → 长引语 0 / 短 0
   ```

3. **反例（证明是真缺陷而非格式自由）**：AGENTS 期刊文章格式把「可迁移表达」列为**第 8 个必备章节**，`新书启动模板.md` 对期刊体裁同样要求——即它是**规则要求的产出物**，却没有任何门禁看它。The Morningside 日志（`09-26.md:76`）已把它列为过程坑第 6 条：「可迁移表达表里的英文必须逐字取自原文——那些不是引语，最容易脱离门禁自造」，但**只作为经验记录，无机检**。

**抽样核验（12 文件 / 47 条 → 7 条 flat 查无 → 逐条回源后 7 条全为真缺陷）**：

抽样粗查得 14% MISS，看似极高。**但 7 条逐条 grep 全部证实为跨行拼接（真缺陷）**，无一为工具误报：

| md 写法 | 原文实际 | 性质 |
|---|---|---|
| `self-deprecation is a literary vehicle` | 第 18–21 行 `that self-deprecation` / `is only a literary vehicle` | 跨行拼接（把 `only a` 删了） |
| `relic from last ice age` | 第 27 行 `a relic I kept from my last ice age` | 跨行拼接（删 `I kept`） |
| `Red Sea standing ovation` | 第 144 行 `the Red Sea, at some point, did a standing ovation` | 跨行拼接（删 `at some point, did`） |
| `love anonymously` | 第 180–189 行 `to love and accept you` / `anonymously` / `and unconditionally` | 跨行拼接（`love` 与 `anonymously` 不相邻） |
| `suck your dick for camaraderie` | `suck your dick **in the bathroom sheerly** for the camaraderie` | 删中间成分 |
| `adaptations not disorders` / `Earth spinning is a time machine` | 同样跨行 | 跨行拼接 |

> **重要口径提示**：这 7 条**都不是"虚构"**——每个词都在原文里，是**跨行/跨段删接**。这与 §3.3 的 A 类虚构性质不同，用 check_vocab 的 A/B 裁决口径处理会误判。**须新增"片段归属"判定**：按 fragment 逐段 flat 命中 + 邻接性检查（与 AGENTS 第 5 条 fragment 取证同源，但判定对象是"词组是否连续"而非"词是否存在"）。
>
> **Ten Bridges 是诗歌回忆录，`text/` 提取件按诗歌换行保留**（原文 `that self-deprecation` 与 `is only a literary vehicle` 之间有 3 个空行）——**自由诗/分行体的提取件天然会把连续句拆成多行**，这正是"跨行拼接假阴/假阳"的高发场景。方案 §3.6 已把 `Very Short Stories by Sean Hill` 等列入待修队列，但**未识别"分行体"这一类**，建议补入。

**提案**：

- **P0-8（新增，紧随 P0-2）**：`check_vocab` 解析词汇表**必须限定在 `## 词汇分级` / `## 本章词汇` / `## 词汇` 节内**——当前 `tier` 变量一经置位**永不复位**（`check_vocab.py:165-170`），任何后续 `##` 节里的两列表格都被当词条。**这不只是可迁移表达**——AGENTS 格式里每章还有「段落脉络表格」「可质疑处表」「表达-含义-场景表」等同类结构，均在污染词条计数。
- **P1 第 4 个脚本 `sweep_analysis_inline.py` 的扫描范围**显式扩到「**所有 `##` 节的表格首列**」，而不只是引语块邻域的行内英文；节名白名单：可迁移表达 / 段落脉络 / 核心金句 / 词汇分级。
- **P2-6（新增）**：「可迁移表达」列入 P2-3"总览只许复制"的同源纪律——**该节英文一律从本章已写好的引语块复制**，禁止另行提炼（提炼即改写）。这条是零工具成本的根因掐断点。

### 12.2 「可迁移表达」污染 check_vocab 的 FAIL/WARN 计数（方向是假绿，不是假红）

**这是 12.1 的机制侧后果，且比 12.1 本身更值得注意**，因为它污染的是**已被方案列为 P0 修复对象的 `check_vocab` 的统计口径**。

Ten Bridges ch22 实测（`python3 scripts/check_vocab.py notes/books/non-fiction/ten-bridges-ive-burnt-by-brontez-purnell`）：

```
词条行合计: 1579
--- FAIL (962) ---
```

- 该书 31 章中，**ch22 实际词汇表 15 行，被计入 79 行**——多出的部分来自可迁移表达表（15 行）与同章其他表格。
- 后果：`check_vocab` 报出的「词条行合计 1579」「FAIL 962」中，**含数百行非词汇表行**。完工通报的「vocab 607 行 FAIL 0 / WARN 0」「vocab 924 词条」等数字（Why We Sleep / One Way Back 等）**分母口径不干净**——若非词汇行恰好全部命中，分母被抬高、FAIL 被稀释；**这与 §3.3「4 列例句不检」是同一个"看起来在检、其实口径已坏"的家族**，但方案 §3.3 只发现了"漏检"，未发现"**误计**"。

**提案**：与 P0-8 同一处修复，**修完须重算全库"词条行合计"并与完工通报数字对账**——口径变了，§3.3 的 1184 行与各书完工数字都需重新出具（§12.4）。

### 12.3 撤回：引语块"静默跳过"不成立（我方自查错误，留痕）

我曾怀疑 §3.4「0 提取假绿」还有一个**更细的形态——单行级静默跳过**（某行形似引语块但 `extract_quotes` 抽不到，而同文件其他行抽得到 → 文件级仍报绿）。三轮扫描得到 2872 / 10367 / 1574 / 455 四个越来越小的数字，**每一个都被自己的下一轮测试证伪**：

| 初版数字 | 证伪方式 |
|---|---|
| 11146 / 10367 | 判据把 `>` 后的内容当块体，但**引语实际在下一行**（`> **原句 N:**` 与 `> "…"` 分两行的合法格式）——`home-sick` ch40 逐行看即证伪 |
| 1574 | 包含关系判断写错（抽中项被多句 join 后不以块体开头）——`all-the-lies` ch21 逐条看即证伪 |
| 455 | 最终归因到「引号后接叙述标签」——这**正是已记录的短引语降级路径**（AGENTS 盲区表：`<20` 字符不校验），One Way Back ch27 早就写过对策 |

**最终可信结论**：单行级静默跳过**不是独立盲区**，全部收敛到已知的 `<20 flat 字符` 短引语机制。**P0-1 的四类分派（§3.6）已足够覆盖**。

> **教训（与 §8.6、§3.3 同源，且是本方案第 5 次同源错误）**：
> ① **"扫描出 N 条异常"不是结论，"逐条回源"才是**——四个数字全部来自"我的判据"而非"原文"，判据错则数字必错。§8.6 已写"引用前先回源"，本次证明**更严的一版：自己产生的统计也要回源**。
> ② **异常数逐轮骤减（11146→10367→1574→455）是判据有误的强信号**，不是"问题在收敛"。真问题的数字应当稳定。
> ③ 这四次错误全部由**我自己的临时脚本**产生，而主门禁脚本一次都没错——又一次印证 §六.1「脚本自身已被证明不可靠」，且风险源是**现写的一次性脚本**，恰是 P1 要消除的对象。
