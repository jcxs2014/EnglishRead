# 子代理派工卡

> **触发**：把一章（或几章）的**起草**交给子代理时读本卡。**定稿与提交仍归派工人**，不外包。
> **依据**：2026-10-20 ch05–ch07 三章实测——子代理的引语逐字、五子项、词汇表、例句全部零缺陷；
> 我复审改掉的 6 处全在**跨章归属 / 计数 / 叙事线**，即门禁结构上查不到的两层（对应、可回溯）。

## 1. 给什么（四件，缺一即缺陷）

| 给 | 具体形态 | 为什么不能省 |
|---|---|---|
| 创建卡 | `docs/rules/创建卡.md` **全文** | 子代理没有路由表，不给就等于凭印象写 |
| 本章原文 | `text/chNN_chapter_N.txt` 的路径 + 要求逐字取引语 | 引语层是唯一能靠脚本兜住的，别在源头放弃 |
| **上游结论** | 前 1–3 章导航里的「一句话概括」**仅这一行**，不是整章 md | 只给一章成品，它会自行脑补跨章关系（ch06 把 ch04 的死亡记成「上一章」） |
| 本书形态 | `python3 scripts/bookform.py --check "<本章 md 或书目录>"` 打印的 profile 行 + 子项集 | 否则它在「profile 的 4 子项」与「本书的 5 子项」之间来回摇摆 |

**不给**：审查表、实测档案、门禁文档全文——防它自审自判、照着判据写。可以给一条 `chapter.sh` 命令。

## 2. 要什么（回执五项，少一项退回）

1. **文件路径 + 字节数**（只说「写完了」不算）；
2. **每块引语的前 6 个词**（让派工人一眼看出块选得对不对）；
3. **事实清单**：谁做了什么、数字是多少、发生在什么时间——每条能回到原文；
4. **最没把握的一处**：明写「哪句是推断、哪句是原文」；
5. **`chapter.sh` 原始输出尾部 + 退出码**（不接受「已通过」三个字）。

> 第 3、4 项是最划算的要求：本次 ch06/ch07 都主动标注了推断（Becky→Zoe 是排除法、口香糖那句是猜测），
> 派工人核实那几处只花了两分钟。

## 3. 派工人必须做（不可省略，也不可转交）

- **a. 素读本章原文**再读它的事实清单——**顺序不能反**（先读 md 就等于用它的理解去核它自己）。
- **b. 抽 2 处跨章指认**回原文核（「上一章」「第 N 章」「前文交代」这类措辞是事故高发区）。
- **c. 跑整书 `gate.sh`**，不能只看 `chapter.sh`（单章过、整书红的情况真实存在）。
- **d. 统一按路径提交**：子代理**不 `git add`、不 `commit`、不 `push`**——多实例共用工作树，谁的暂存区谁负责。

## 4. 配额与拆分

- **一次 ≤3 章并行**，每章一个独立子代理；**不要**让同一个子代理连写多章（它会开始模仿自己）。
- 已完工的书不再派工；派工只用于**新书起草**与**整章重写**，不用于修补（修补要逐条核，比重写贵）。

## 5. 已知边界

子代理**看不到别的章**，因此下列三类它必然可能出错，**只能靠第 3 节 b 步兜住**：

| 错法 | 本次实证 |
|---|---|
| 跨章归属（把甲章的事记成乙章） | ch06 说「上一章 Chloe 死在地窖」，ch05 全章无一字提及死亡 |
| 叙事线判断（把「推测」写成「确认」） | ch05 说「前四章还是推测」，而 ch04 已写出地窖里的死亡 |
| 可计数断言 | ch05「六个词」实为八个；ch07「三处星号」实为一处 |
