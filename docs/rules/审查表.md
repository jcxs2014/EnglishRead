# 审查表 · 同会话审查一章 / 一批

> 前提：审查方与写作方是同一个会话。独立性只来自两件事——**读取顺序**与**实现路径**。
> 落盘：`.memory/raw-gates/<slug>/review/chNN/`，随书归档，第三方可重跑。
>
> **默认档位是「快审」**（2026-10-22 用户拍板，约 20 分钟）；本文件后半的 R0–R5 是
> **深审**，只在升级条件命中时执行，且**升级须经用户确认**。

## 0. 两档审查（先选档，再动手）

| | **快审（默认）** | **深审（触发式）** |
|---|---|---|
| 适用 | 所有新完工的书 | 命中下方任一升级条件 |
| 机器层 | `gate.sh` + 逐字严格比对 + `overview.py quotes\|full` | 同左 |
| 总结层 | **全读**：概述 + 每章一句话总结，**按六类逐句过**（身份 / 关系 / 谁做了什么 / 谁欠谁 / 谁被替罪 / 数字），每条回 `text/` 找到支撑行——**不许用「读起来对不对」代替清单** | 同左 |
| 全局实体 | 人名 / 关系 / 年龄 / 时间线 / 数字跨章 grep 交叉 | 同左 |
| 章内 | **抽 1/8 章**（2026-10-22 用户定）＝ `ceil(N/8)`，**最少 2 章、最多 6 章**；**首章与末章必含**，其余等距取；双视角书优先取有姓名小标题的章 | 未抽章走 R1–R4（全量） |
| 产出 | **一份 ≤40 行清单**：位置 / 改前 / 改后 / 原文依据 | 判定表 + 修复指令 |
| 用时 | **约 30–40 分钟**（27 章书 ≈ 4 章） | 90–180 分钟 |

### 升级条件（任一命中 ⇒ 提请用户确认，**不得自行升级**）

1. **快审本身查出 ≥3 条阻断**；
2. **书写时没用生产端设施**：没有 `bookform.py --contract`、没有素读清单（`suread.py`）、
   或该书是「事后补审」而写作时引语粒度规则尚未生效；
3. **机器层出现异常信号**：引语中位 >100 词、块数越界、模板套话 >0、或 gate 反复红又反复绿；
4. **用户点名**。

> ⚠️ 没有用户确认，不许把 30–40 分钟的快审自动膨胀成 90–180 分钟的深审。
>
> **抽 1/8 章是下限，不是上限**：命中升级条件时可以加抽，但加抽同样要用户确认。

### 快审记账（每次都要写，一行）

追加到 **`.memory/review-ledger.md`** 的表格末尾：

```
| 2026-10-22 | <书 slug> | 快 | 18 min | gate 0 / 严格 0 / 总览 56/56 | 总结层 1 · 实体 0 · 章内 0 | 1 | 否 | 金句 ⑨ 与 ㉖ 同句重复 |
```

字段：日期 ｜ slug ｜ 档位 ｜ 用时 ｜ 机器层结论 ｜ 总结层·实体·章内各查出几条 ｜ 合计 ｜ 是否升级 ｜ 备注。
**用途**：跑十几本之后用数据判断 20 分钟够不够、升级条件该调高还是调低——**别凭感觉定档**。

## 0.5 先对齐生产步骤，再打靶

审查不是「再读一遍」，是**按生产流程逐站查它在生产中真正会失手的地方**。
五站（S1 读原文 / S2 选引语 / S3 写分析 / S4 词汇 / S5 总结与总览）各有哪些典型失误、
对应哪个探针、什么档位，以及**按章型加权的抽样规则**（首章 / 重述章 / 对话密集章 /
cliffhanger 章 / 末章必查，其余按 S3 机器层兜底）见 **`docs/rules/生产-审查对照.md`**。

- 机器能判的先跑（S3 密度与夹杂、S4 词汇、S5 引语）；人只处理机器结构上查不了的**五类**：
  **漏 / 对应 / 说话人 / 施事归属 / 事实断言**。
- **优先「按成因类预筛」，而不是「按章抽」**（2026-10-21 实证：the-dues 43 章 1290 行分析子项 →
  按「人数 / 否定域 / 说话人 / 归属方向」四类成因扫出 270 行候选，**覆盖 43/43 章**，比扩抽 32 章小两个数量级）。
  缺陷按**成因**聚集，不按**章**聚集；章节抽样只是补充，用来补「成因类想不到的」那一层。
- **机器门禁的 100% 只覆盖它读的那一层**：`verify_quotes` 487/487 是「引语英文逐字」，
  不含中文语义（谁说的 / 谁欠谁 / 时间轴 / 人数 / 否定域）。⇒ 不许用「机器全绿」推出「缺陷都在摘要层」。
- **全章 R1 成本高，但抽样不许省掉「按章型」这一层**——随机抽 3 章会正好错过 cliffhanger 与重述章，
  而错配与跨章搬句几乎都发生在这两类。

**最小抽样配置（2026-10-21 两本书实测：3–4 章人判各抓出 2–5 条阻断，全部落在这几类章里）**

| 时间 | 必读章 | 覆盖 |
|---|---|---|
| 15 分钟 | **首章 + 末章 + 概述全篇** | 建立 / 收束 / 全书断言 |
| 1 小时 | 加 **对话或技术密集章** + **重述/回忆章** | 拼接、说话人、施事反转、版本混淆 |
| 充裕 | 加 **cliffhanger 章**、**来信/多视角章** | 归属与「她的版本」 |

抽样章号与理由写进 `4-verdict.md` 的覆盖声明；**没跑的章要写「只有机器层」，不许写成「通过」**。

## 深审 · 铁律：先素读，后开 md

> 以下 R1–R5 属**深审**（约 90–180 分钟），只在 §0 升级条件命中且**用户确认**后执行。
> 快审不读本节，但**「先素读后开 md」这条纪律对两档都成立**：快审抽的那 1 章，仍要先读 `text/`。

打开任何一章 md 之前，**必须先完成 R1**。违反这条，本次审查结论作废——那等于自己批改自己刚写的作文。

## R1 素读（只读 `text/chNN.txt`）

产出 `1-suread.json`：5–8 条「谁做了什么」+ 人物关系 + 数字/日期，每条带**原文字符区间**。

- 不许看 md、不看笔记、不回忆；
- 事件粒度到**动作**，不到气氛（写「X 把信烧了」，不写「气氛紧张」）；
- 数字逐字抄。

## R2 机器层（第二实现，不读 md 的结构）

```bash
bash scripts/chapter.sh "<书目录>/chNN 标题.md" --json > 2-machine.json
```

全部从 `text/` 重建、再与 md 对账，做四件事：

1. 引语逐字（省略号分段**独立取证**，不整串比）；
2. 块清单：md 有几块、每块引语落在原文哪个区间；
3. 形态：H1 / 导航项 / 子项集 / 块数 vs **本书众数**（偏离要理由）；
4. 中文密度：每块分析 CJK 字数与占比。

`chapter.sh` 的退出码：0 无阻断 / 1 有阻断 / 2 无法判定（缺语料）。**2 不是通过。**

## R3 对账（三张单子）

| 单子 | 判据 | 档 |
|---|---|---|
| **漏**：素读有、md 无 | 关键事件/转折未出现 | 阻断（除非 md 写明取舍理由） |
| **编**：md 有、原文无 | 情节/关系/数字凭空出现 | 阻断 |
| **错**：两边都有但不一致 | 主语、因果、数字、时序 | 阻断 |

逐条写进 `3-diff.md`，每条附两侧原文。

## R4 逐块对应（人判，唯一不可机械化的一步）

不看子项标题，只回答一个问题：**这段中文是不是在讲这句引语？**

- 讲的是引语之外的上下文 → 引语选短了，退回创建卡 §2 ①；
- 讲的是全书主旨/作者生平 → 不对应；
- 只复述字面、没有「为什么这样写」 → 密度不足。

**固定追问（对应 S3 第 ⑥ 类「施事/归属反转」）**：这块中文里
① **每个动词的主语是谁**、② **受事/宾语是谁**——和原文那一句一致吗？
③ 「谁的 / 谁欠谁 / 谁问的」这类归属，**回原文看 `by` / `to` / `from` / `of` 决定方向**。
这类错四道机器探针全绿（引语逐字、中文是中文、关键词成立、形态正常），只有这一问能抓。

## R5 判定表

`4-verdict.md`：`断言 | 证据（章:区间） | 结论 | 档位`

档位四个：**阻断**（与原文不符/缺失）、**提示**（措辞正当）、**假红**（工具判错）、**跳过**（没查）。

报数只报四组：**逐字 / 对应 / 形态 / 断言**——不给单一「阻断 0」。

### R5-补 · 「零命中」类断言必须先自证（2026-10-21 立 · 2026-10-21 订正机制）

凡是写成「全书查无 / 零命中 / 从没出现过」的断言，**必须附上原命令、输出与退出码**，并在 `4-verdict.md` 里留一行：

```
取证命令：/usr/bin/grep -cE 'lightning|struck by' notes/books/<书目录>/text/*.txt
         → 命中 1（text/ch10:265）；退出码 0
```

**为什么加**：审查方连续两轮把「零命中」报成缺陷前提，回原文一查全是**取证工具用错**，不是原文没有。

- ⚠️ **2026-10-21 机制订正**：本条初版把原因写成「macOS 的 BSD grep 里 `\|` 不生效」——**本机实测不成立**：
  `/usr/bin/grep` 是 BSD grep 2.6.0-FreeBSD（GNU compatible），`grep -c 'lightning\|bolt' text/ch10_*.txt` **得 2 命中**，
  原文 `text/ch10:265` 明写 "It's like seeing someone get **struck by lightning five times** in a row and still be alive."。
  ⇒ 真正的机制是：**`text/` 被 `.gitignore` 排除（`.gitignore:132 notes*/books/**/text/`）⇒
  `git grep` 与默认尊重 ignore 规则的 rg 系在该目录上永远「查无」，且 `git grep` 的退出码 1 与「真查无」不可区分。**
  ⇒ **只把模式改成 `-E` 防不住**（模式改对仍然为空）——**要换的是工具类型，不是模式写法**。
- 同类假零命中：模式与原文用词/词形不一致时同样为空（原文 `text/ch25:137` 是 "Behind him were **seven other** soldiers"，
  查 "seven soldiers" 必然查无）；纯子串会误命中（`bolt` 命中 `text/ch10:217` 的 "bolt out the front door"）⇒ 查单词用 `-w`。

⇒ **取证三件套**：① **显式文件路径**（用 `/usr/bin/grep` 或 Python 读文件；**不用 `git grep`**、不用 rg 系默认 ignore 规则）
② 交替匹配用 `-E`、查单词用 `-w` ③ **贴命令 + 输出 + 退出码**（`cmd > /tmp/o 2>&1; echo $?`——接管道会吞退出码，`&&` 链会短路）。
给不出命令与输出的「查无」，只能写成「未核」（跳过型），不能当阻断依据。
工具选择的细则见 `docs/rules/30-writing.md` 坑字典 **7b**；判例见 `docs/实测档案/AA_2026-10-21_零命中取证机制订正.md`。

### R5 硬约束：无原文逐字，不得判阻断

每条「阻断」必须带 `text/<文件>:<行>` 与**该处原文逐字**（`4-verdict.md` 的「证据」列）。
给不出逐字证据的，**只能写「未核」**，不许写「阻断」。

> 来历：2026-10-21 复核 capture，我自己先怀疑了 3 处（遗孀信里的「绝症」、给牛吹小号、Caitlin 译名），
> 回原文一查**书写得对**——「绝症」是 Sandra 亲口说「I told them he had a terminal illness」。
> 没有这条约束，这 3 条就会以「阻断」发出去，让对方去改本来正确的内容（同 the-glass-girl ch07）。

## R5.5 已核实为正确（防误修，固定一节）

`4-verdict.md` 末尾固定写一节「**已核实为正确**」：列出**看起来像错、回原文核对后成立**的写法，

## 同会话三条自律

1. **先落盘再判**：md 改完立刻 commit，再开始审查；不要边改边判。
2. **一次只改一处再验判据**：批量改 10+ 处同类之前，先改 1 条确认判据成立。

## 审查会话的编排纪律（2026-10-22 实测）

> 来历：`don-t-leave-her-alone` 的审查会话跑了 **20.8 小时 / 2,518 次调用 / 39 个子代理 / 63 次压缩**，
> 产出 19 份判定表。判定质量合格，但**管理子代理的成本超过了审查本身**——典型片段是
> 「子代理跑 20 分钟只写出一个脚本」「主会话 `sleep 240 → 420 → 540` 轮询」。
> 同一人审 `the-dues` 43 章（3 章素读 + 全量机器层 + 写指令）约 1.5 小时。

1. **审查不按章并行**：每章派一个子代理 + `sleep` 轮询，得到的不是吞吐而是空转。
   审查是串行判断，一次一章往前走，写完立刻落盘。
2. **子代理只用于生产（起草章节），不用于审查**。确需并行时一批 ≤3，
   派工单只给 `text/chNN*.txt` 路径与判定口径，**不给审查表全文**（它会照抄结构、把表当模板填）。
3. **合并多份判定表时按短语 `grep` 复核，不按行号**：审查期间书稿被持续修改（本案 23 次修复提交），
   判定表里的行号会整体漂移；结论要落到「哪个短语还在不在」。
4. **先快审**：按 §0 的 `ceil(N/8)` 抽样跑；只有用户明确要求深审，才做全章人工层。
   两者都要在判定表里写明覆盖到哪一步，不许用快审的结论冒充深审。

## 报警复核（不分类不许照单全改）

- 成片同类报警：先 `sed -n` 读 2–3 行，**先假定工具口径错了**，再假定内容错了；两种可能都要排除。
- 判错的进 `4-verdict.md` 标「假红」，并把口径修进工具，不修 md。
- 判对的标「阻断」，改完重跑 R2——**「现在 0」不等于「每处都修过」**，报告要给修前→修后。
