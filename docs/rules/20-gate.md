## 1. 跑什么

```bash
bash scripts/gate.sh "<书目录>"                  # 书级：19 lane 一次跑完
bash scripts/chapter.sh "<章 md>"                # 章级：写作时每章跑
python3 scripts/sweep_journal.py "<日期目录>"     # 期刊
python3 scripts/verify_corpus.py "<书目录>" --expect N --expect-source "…"   # 新书第一步
```

`gate.sh` 依次跑：**`quotes.py verbatim`** / check_vocab / check_entities / corruption_scan / **`quotes.py full`** /
**`quotes.py short`** / **`quotes.py chapter`** / **`quotes.py coverage`** / check_nav_layer / sweep_analysis_inline /
audit_structure / check_anchor / 空段扫描 / verify_overview_quotes / check_overview_full /
check_xref_chapter / **`quotes.py blocks`** / check_block_keywords / check_chinese_layer。
引语层那六件事已收进 `scripts/quotes.py` 一个入口（旧脚本名 → 新命令见 `工具登记.md` 末尾）。
（lane 清单会变，**以 `gate.sh` 现场为准**；单跑某检测器的参数见该脚本 `--help`。）

**结论怎么来的（2026-10-20 起是双轨）**：`gate.sh` 同时看两层——
**退出码层**（`②③⑦⑧⑲` 这五道的进程退出码：1=阻断、2=未判定）与
**文本层**（日志里 `❌` 条目行计数，覆盖其余 lane）。
任一层报阻断 → `exit 1`；两层不一致时**脚本会把不一致本身打印出来**——那正是
2026-10-02 / 10-05 / 10-06 三次「汇总层把真阻断洗成绿灯」的形态。
⚠️ rc 层**只覆盖五道**，因为其余工具的退出码语义还没逐个核实
（多个工具把 ⚠️ 提示也计入非零码）；**盲目扩大 rc 层会把提示型判成阻断，在全库制造假红**。
读输出时先看末尾那两行，再看是哪一轨报的。

## 2. 先判 lane：有 epub / 无 epub

| 判定 | 完整 lane（有 epub） | 降级 lane（无 epub） |
|---|---|---|
| 例句是否命中本章 | 权威 | 权威，照常判 |
| 引语是否逐字在全书 | 权威 | **不出结论**：exit 2 +「❓ 无法判定」 |
| 词条是否 A 类虚构 | 权威 | 不出结论，列「❓ 无法判定」 |

**降级 lane 不是"检查通过"，是"部分检查没做"**——报告必须写清 lane，不得与完整 lane 的数字混用。

## 3. 四档处置（报警不是同一种东西）

| 档 | 处置 | 判据 |
|---|---|---|
| **阻断型** | 必须改 | 数字对不上＝内容错（`verify_quotes` 非 100% / `check_vocab` FAIL / `check_chapter_quotes` MISS / `corruption_scan` FAIL / 未知实体 / `audit_numbers` 差≥2） |
| **提示型** | 只记不改 | 内容本身成立、只是量具判不准（`audit_numbers` ❓ / 基础档疑超纲 / `check_anchor` ⚠️） |
| **假红型** | 先修工具 | 工具坏了（小样本缺章节 / `ch_corpus` 为空 / 空跑） |
| **跳过型** | 先修工具，并把「未核」写进报告 | 报"0 条"但内容根本没进扫描集 |

**七条纪律**（每条都来自实证，案例见档案）：

1. **先分类再动手**：不分类照单全改会改坏正当内容（14 章实测：阻断型 100% 真缺陷，提示型 100% 正当措辞）。
2. **提示型有硬前提：内容本身成立**。内容缺失（中文理解写成英文、整段英文）一律阻断型，不是措辞问题。
3. **成片报警先读 2–3 行**：既要排除"工具口径错"，也要排除"整层没写"，两种可能都得查。
4. **量级**：某类提示型超过本书引语块 30% ⇒ 先抽 20 条人工定性，才可申报完成。
5. **修复类报告给类级对账**（「中文理解纯英文 146 → 0」）+ 改写方式；只报「0」与「没查」在文本上无法区分。
6. **分档可被推翻**：执行方自报的分档，用户与异实例均可推翻；板上「五步审查通过」是申报，不是终局。
7. **验「已修」要验被修的那一刻**：「现在没有」≠「从来没有过」；自查死链时区分「提及某文件」与「指引读者去读某文件」。

## 4. 新规则适用范围

| 类别 | 例子 | 回溯重跑 | 回溯改 md |
|---|---|---|---|
| **判据变更** | 块数改同书自校准、新 lane 进门禁、`--wide` 转默认 | — | ❌ 只对新增书籍 |
| **工具失准** | 工具声称做却没做到（如 `check_entities` 丢整节） | ✅ 精准重跑受影响的书并留档 | ❌ 不自动改 |
| **只报不判红** | 反向对账、取证模式 | ✅ 随手跑 | ❌ 不自动改 |

1. **判据变更只对新增书生效**；已完工的书不自动回溯重判、不自动回溯改内容。
2. **工具失准必须重跑留档，但只跑受影响的书**；重跑 ≠ 整改，出真缺陷逐本单独决定。
   - 基线取**修前**那版：`BASE=$(git log -1 --format=%H -- scripts/<检查器>.py)`，再用 `git show <BASE>^:<path>`；**不能用 HEAD**（修复已 commit 时 HEAD 是修后版，比对必然「0 本受影响」）。
   - 收窄口径：只有 `❌` 明细增删才算受影响；汇总行与只报行变化不算（实测 341/384 本"有差异"，明细真变 17 本）。
   - **误报率高的工具不进回溯**（`verify_fragments_indep` 假红 93.5%、`check_quote_order` 会让 341/483 本变红）——只写结论，不生成基线文件。
3. **返修书按「改动即适用新规则」**（touched-on-write）：改哪部分，哪部分按新规则核。
   - 新旧粗判：`git log -1 --format=%cs -- "<书目录>"`；**禁止让工具自己推断"这本是不是新书"**（会漂）。
   - 留档落点：`.memory/raw-gates/<slug>/<日期>-baseline-<检查器>.txt`；**exit 2（无法判定）也要留档**。
