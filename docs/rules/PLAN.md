## 1. 目的

1. 一本书 → 逐章精读 md（+ 总览三篇）；一篇文章 → 一篇 md。格式随本书既有形态，不套全局模板。
2. 精读必须**忠实于原文**。忠实不是一句话，是四个可分别验收的东西（见 §2）。
3. 成本要撑得住长篇（30–100 章），且写完当场能自查，不依赖另一个会话。

## 2. 质量判据：忠实四问

| 类 | 问 | 现在谁在管 |

| 逐字 | 引语在原文里一字不差吗 | 11–12 个 lane（已过度覆盖） |
| 对应 | 分析讲的是这一段吗 | `chapter.sh` 弱覆盖 + R4 人判 |

## 7. 写规则的判据（新增/删除时逐条过）

1. **三问**：这条规则现在有几个载体（>1 → 留一个）？删了它内容去哪（答不出 → 不许删）？新增的这份替掉了谁（答不出 → 它是第五份副本，不要加）？
2. **三类合法删除**：已在新载体落盘并核对过的 / 纯运行数据与临时产物 / 已被 git 历史覆盖的重复副本。
3. **数字不硬编码**：lane 数、脚本数、本书数一律写"以现场命令为准"。
4. **体积预算**：`docs/rules/` 合计 ≤40 KB，超了必须置换不能追加。
   现状 57.9 KB（2026-10-20），**已超 17.9 KB**——主因 `20-gate.md` 18.6 KB 保留了第 3 条全部历史注解。
5. **判例不进规则文件**：规则文件写判据与处置，个案进 `docs/实测档案/`。

## 步骤 5 结论：raw-gates 现在**没有**可删的余地（2026-10-20 实测）

原计划写「保留最近 30 天 + 每本书最后一次，其余 `git rm --cached`」。实测推翻了三点：

1. **「30 天」永远剪不到**：全库最早的运行是 2026-10-11（距今 9 天）——这是活跃库，
   按天数剪枝等于没有策略。
2. **「每本书最后一次」只能删 132 / 2,315 个文件（5.7%）**：同一次运行本身就有几十个文件
   （逐章 + 全量门禁 + 各 lane 分件），真正的体量不在「历史运行太多」。
3. **原件被引用钉死**：`docs/`、`.memory/daily/`、`COLLABORATION.md` 里有 **193 处**
   按「目录/文件名」引用具体某一次运行的原件。删掉即断链，而引用检测只能认出
   **9 个**可保护的（slug, 文件名）对——检测不完美，删了会静默断链。

⇒ **政策（已生效）**：
- 证据**保持入库**，不因体积删；`.memory/raw-gates/` 仍是唯一允许的过程落盘点。
- 每本书**只保留最近一次运行**是目标态，由 `scripts/prune_raw_gates.py` 执行（默认演练、
  自动跳过被引用文件、最新一次不完整的目录整目录跳过）。
- **每季度**跑一次 `python3 scripts/prune_raw_gates.py` 看增长；确认无引用断链风险再 `--apply`。
- 真要让仓库变小，正确方向不是删证据，而是**证据文件本身瘦身**（gate 输出只留汇总行，
  逐条明细进 git 历史或按需重跑）——那是 gate.sh 的改造，不在本步范围。
