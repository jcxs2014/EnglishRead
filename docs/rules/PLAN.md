## 1. 目的

1. 一本书 → 逐章精读 md（+ 总览三篇）；一篇文章 → 一篇 md。格式随本书既有形态，不套全局模板。
2. 精读必须**忠实于原文**。忠实不是一句话，是四个可分别验收的东西（见 §2）。
3. 成本要撑得住长篇（30–100 章），且写完当场能自查，不依赖另一个会话。

## 2. 质量判据：忠实四问

| 类 | 问 | 现在谁在管 |
|---|---|---|
| 逐字 | 引语在原文里一字不差吗 | 11–12 个 lane（已过度覆盖） |
| 对应 | 分析讲的是这一段吗 | `chapter.sh` 弱覆盖 + R4 人判 |
| 可回溯 | 事实/数字断言回得到原文吗 | **零覆盖** → R1 素读 + R3 对账 |
| 不漏 | 关键内容没被略过吗 | **零覆盖** → R1 素读（先读 text 后开 md） |

## 3. 两步流程

- **创建**：`docs/rules/创建卡.md`（三句话 / 开工命令 / 生产五步 / 门禁四档 / 三条硬线 / 三条禁令）。
- **审查**：`docs/rules/审查表.md`（R0 铁律 → R1 素读 → R2 机器层 → R3 漏编错 → R4 逐块对应 → R5 判定表）。
  - 独立性来源＝**把读的顺序倒过来**：R1 先只读 `text/chNN.txt` 写素读，写完才开 md。
  - 审查包落 `.memory/raw-gates/<slug>/chNN/`：`1-suread.json`、`2-machine.json`、`3-diff.md`、`4-verdict.md`、`run.sh`。
  - 第三方复核三步：跑 `run.sh` → 比 `2-machine.json` 哈希 → 抽 3 行 `4-verdict.md` 回原文。


## 7. 写规则的判据（新增/删除时逐条过）

1. **三问**：这条规则现在有几个载体（>1 → 留一个）？删了它内容去哪（答不出 → 不许删）？新增的这份替掉了谁（答不出 → 它是第五份副本，不要加）？
2. **三类合法删除**：已在新载体落盘并核对过的 / 纯运行数据与临时产物 / 已被 git 历史覆盖的重复副本。
3. **数字不硬编码**：lane 数、脚本数、本书数一律写"以现场命令为准"。
4. **体积预算**：`docs/rules/` 合计 ≤40 KB，超了必须置换不能追加。
   现状 57.9 KB（2026-10-20），**已超 17.9 KB**——主因 `20-gate.md` 18.6 KB 保留了第 3 条全部历史注解。
5. **判例不进规则文件**：规则文件写判据与处置，个案进 `docs/实测档案/`。
