# 8.2 禁令 2 与 3 的收窄说明与案例

> 2026-09-27 从 `AGENTS.md` 迁出。**规则本身全部留在 AGENTS.md**（那是每本书开工都要读的），
> 迁出的只是**每个规则背后的完整案例叙述**（书名、章号、错在哪、怎么改）。AGENTS.md 现只保留
> 「规则句 + 案例数字 + 指向本档案的指针」。
>
> 触发迁移的直接原因：AGENTS.md 一度 103.9 KB，而 harness 的指令注入预算只有 65,536 字节
> ——**尾部 35% 从未进入任何新会话的上下文**（整张「工具已知盲区速查」表与 git 策略节都在里面）。
> 这是平台硬约束：**没进前 65 KB 的规则，对新会话等于不存在。**

   禁令 2 与 3 是**有例外地收窄**而非一刀切：可核的计数与证据性引文保留，
   不可核的计数与术语记法才排除——**保住分析价值，不牺牲严谨度**。

   ⚠️ **禁令 3 是本库唯一「事后无低成本机检」的缺陷类（2026-09-27 实证）**：
   Society of Lies 五步审查在**九道门禁全绿**的前提下，用换路径扫描查出
   **22 处分析层伪造/改写引语**——`sweep_analysis_inline` 报 77 条 🟠，真缺陷只是少数、
   **淹在噪音里**；`verify_quotes` 不看分析层，`check_anchor` 也不看。
   **结论：这一类只能靠写作期粘贴，事后补检代价远高于收益。**
   两个附加实证：① **修 A 时极易再造 B**——整改时凭印象写的替换文本
   （`I'm not here to confess to a crime`）同样全书查无，靠二次扫描才自抓，
   **替换文本写入前必须先 flat 比对**；② **「软化改写」是伪造的一种隐蔽形态**——
   把原文的种族歧视辱骂改写成 `Dirty chinks` 会被当成无害措辞放行，
   **改动引语字面时不存在「只是润色」这回事**。

   （**编号对照**：本节沿用整理期的迭代编号 `1a-2`（逐条验）/ `1a-3`（特殊字符）/ `1b`（原词形）；**现行禁令表已把 1b 并入 1a、1a-3 保留为 1c**，见表 8.2。）

   ⚠️ **禁令 1a 的实测结论比禁令本身更重要**：补齐「逐条验」之后，
   词表初稿缺陷率只从 43% 降到 42%——**检查型规则不降低缺陷率，只提前发现**。
   真正把缺陷压到 0 的是 1a 的**前半句（用脚本产出）**。
   详见 8.5「检查型规则不减少缺陷」小节。
