## 模型内容审核限制（预判优先）

> 遇政治/暴力/宗教/种族等可能触发审核的段落，**先预判、先委派子代理**，不自行分析；
> 若仍触发 1027 中断，**告知用户后按原文继续，不绕过、不改写、不换说法**。
> 完整流程见 `docs/实测档案/D_敏感内容审核限制.md`（该节自 2026-08-21 起自标「当前会话模型可能不是 MiniMax」，
> 仅在确实命中审核限制时才需读）。
> **备注（2026-08-21）**：当前会话模型可能不是 MiniMax；子代理系统故障时（如 task 工具报 DB 错误），敏感文章由主会话直接谨慎处理，不阻塞批次进度。

### 第一层：主动预判，提前调用子智能体
当主代理（MiniMax）准备分析的内容涉及以下可能触发内容审核的话题时，**应在输出之前预判并主动处理**：
- 政治、政治人物、国家/地区争议
- 暴力、战争、恐怖主义
- 宗教、民族、种族话题
- 争议性社会议题
- 任何可能被 MiniMax 审核系统判定为敏感的内容

遇到上述内容时：
1. **不要自行分析该段落**
2. 直接通过 Task 工具调用 `english-read` 子智能体，把当前段落原文 + 已完成的分析进度 + 完整上下文传给子智能体
3. 由 `english-read` 子智能体完成该段的精读分析
4. 主代理负责其余不敏感部分的分析，并整合子智能体返回的结果

### 第二层：1027 兜底（预判失误时）
如果预判失误、仍触发了 `output new_sensitive (1027)` 审核报错（生成被中断）：
1. 告知用户："我遇到了 MiniMax 内容审核限制（1027），请对我说'继续'，english-read 子代理将接管后续分析"
2. 不绕过、不改写、不换方式表达相同内容

作为 english-read 子代理，当收到含"1027"或"敏感内容限制"或"敏感段"的任务时：
- 直接承接当前上下文（已完成的分析进度、当前文章进度、剩余待分析段落）
- 从主代理中断处继续分析下一部分，或完成被委托的敏感段落分析
- 不重复已完成内容
