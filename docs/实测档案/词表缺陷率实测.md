> 迁出的只是**每个规则背后的完整案例叙述**（书名、章号、错在哪、怎么改）。AGENTS.md 现只保留

   ### ⚠️ 检查型规则不减少缺陷——只有生产型工具才减少（2026-09-26 六章实测）

   > **本小节是上述「最高主张」在词表层的原始取证**，现已提升为第 8 条开头的顶层主张。
   > 这里保留完整数据；引用时以顶层主张为准。

   写完 1a / 逐条验 / 特殊字符 / 原词形（整理期编号 1a / 1a-2 / 1a-3 / 1b）之后我一度宣称这些禁令能减少缺陷。**实测不支持。**

   | 章 | 词表初稿缺陷率 | 验法 |
   |---|---|---|
   | ch33 / ch45 / ch05 / ch11 / ch24 / ch04 | 14% · 18% · 23% · 27% · 32% · 43% | 统一验 |
   | **ch06（首条按 1a-2 逐条验）** | **42%** | 逐条验 |

   **补齐 1a-2 之后缺陷率 43% → 42%，几乎没变。** 1a-2 改变的只是
   **发现时机**（当场 vs 写完），不是缺陷本身。

   **原因是这六条禁令全部是「检查型」**：它们说「写完验」「逐条验」「用原形」，
   而缺陷发生在**动笔那一刻**（凭印象写词条），检查只能事后拦住。
   **凡「检查型」规则都别指望它降低缺陷率——它降低的是返工量。**

   **治法是换生产方式**：`scripts/vocab_candidates.py` 直接从 `text/` 打出
   **可粘贴的三档表格行**（词头与例句都由脚本从原文取）。
   实测 **4 章 87 条候选、缺陷 0**；对照手写同规模词表 42% 缺陷率。
   **「例句伪造」与「词头非原形」两种缺陷在结构上不再可能发生**，
   我唯一可能写错的只剩释义——那是 WARN 不是 FAIL。
   **且它敢诚实输出「本章 0 条高级」**（ch45 实测），而硬凑三档必然开始编——
   **这比任何禁令都更有效地执行了 1a-2 的「少写几条」**。

   **写词表的默认流程因此改为**：

   ```bash
   python3 scripts/vocab_candidates.py "<书目录>" --ch NN --tiers --limit 12
   ```

   粘贴 → **只填释义列** → 三档条数不够就**留空，不要补**。

   ⚠️ 这不违反「报警 > 0 补规则、不加脚本」——那条针对的是**检测脚本**
