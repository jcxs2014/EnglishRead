# 第 3 条 epub 规模实测更正

> 2026-09-27 从 `AGENTS.md` 迁出。**规则本身全部留在 AGENTS.md**（那是每本书开工都要读的），
> 迁出的只是**每个规则背后的完整案例叙述**（书名、章号、错在哪、怎么改）。AGENTS.md 现只保留
> 「规则句 + 案例数字 + 指向本档案的指针」。
>
> 触发迁移的直接原因：AGENTS.md 一度 103.9 KB，而 harness 的指令注入预算只有 65,536 字节
> ——**尾部 35% 从未进入任何新会话的上下文**（整张「工具已知盲区速查」表与 git 策略节都在里面）。
> 这是平台硬约束：**没进前 65 KB 的规则，对新会话等于不存在。**

   **实测规模（2026-09-26 复核更正）**：全库 355 个书目录中 **100 本（28%）有
   epub**；其中**仅 11 本同时具备 `text/` + md**（=「材料完整 11 本」，门禁能力
   最全），**另 89 本只有 epub、无 md、无 text/**——它们是**已投喂待精读的新书**，
   epub 对它们是必需品。**旧文写的「11 本（3%）」是错的**，根因是
   `find -maxdepth 3` 而 epub 在第 4 层（`<类>/<slug>/library/x.epub`），少一层量成 0/11。
   **降级 lane 的书不是"检查通过"，是"部分检查没做"**——报告里必须写清 lane，
   不得与完整 lane 的数字混用。epub 留存策略**已定**（见「书籍精读原文核验」的
   新 epub 归档流程与下方 epub 条），故本表按 lane 表述而非假定 epub 总在。

   **🚦 门禁结论必须分三档（2026-09-26 确立）**
