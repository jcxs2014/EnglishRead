# X · 规则体系审计与重构依据（2026-10-20）

> **这是审计记录，不是规则。** 规则见 `docs/rules/`，进度见 `docs/rules/PLAN.md`。
> 起因：用户问「规则文档和各种脚本有没有改进空间」「对大模型来说，规则太多是不是一种负担」「没有规则，文档质量又无法保证」。
> 本文把那一轮讨论的**证据与结论**固定下来，防止以后只剩结论、没有依据。

## 一、结论（先看这五条）

1. 负担的主要来源是**规则、判例、操作手册、验收标准混在同一个文件里**，并且要求顺序通读；问题并不在条数本身。
2. 规则成本集中在四处（§三），最大的一处是**上下文压缩后重读模板**，单次 11 万字符。
3. 真正伤害质量的是**目标函数被替换**：可机检的「引语逐字」做到极致，读者最刺眼的「谁做的 / 什么关系 / 有没有漏」零覆盖（§五）。
4. **检查型规则会无声失效**：19 个 lane 里有全库 100% 跳过的，有把 2,277 行带标注引语判成「无引语」的（§六）。
5. 有效手段是**更换生产方式**；增加检查通常不解决问题（§七，三组对照实验）。

## 三、四笔成本账（为什么慢）

| # | 成本项 | 量级 |
|---|---|---|
| ① | 模板全读（开工必读） | 111,697 字符 / 本 |
| ② | **压缩后重读模板**（`docs/新书启动模板.md:231` 明文要求） | 112k 字符 × 每本约 10 次 ≈ **百万字符** |
| ③ | 终验清单逐项划 ✓（`:800` 起） | 30,071 字符 × 每 commit；实测约 **1 commit / md**（the-dues 46 md / 25 commits；don-t-leave 21 / 20；finding-darla 26 / 1） |
| ④ | 双 AGENTS 注入 | 26,981 + 33,312 = 60,293 字符/轮 |

对照：`gate.sh` 跑完一本书 **1.5–2.8 秒**。同一批判据，机器 1.5 秒，人抄 30,071 字符——③ 是纯浪费。

⚠️ ④ 还暴露一件事：**注入量不能当地基**。文档说「只注入 4,882–8,009 字符」，而本轮会话整份 `AGENTS.md` 与 `.memory/AGENTS.md` 都被注入。两处必有一处过期，所以设计目标定成「按最小实测预算（4,882 字符）能装下」，不赌实际注入多少。

## 四、规则为什么会长成这样（腐化证据）

- **「唯一副本」承诺在文件里出现 9 次，实际失效 4 次**——同一条判据存在 3–5 份副本，且已漂移（2026-09-27 实测）。
- **数字硬编码必漂**：lane 数文档写 15/13、实 18/19；脚本数 80→86；`scripts/gate.sh:329` 标题仍写「块数配额 3–8 处」，而实现早已改为同书自校准。
- **补丁密度**：模板含 156 个 2026 日期戳、146 个 ⚠️、9 处「唯一副本」、142 个「必须」。这不是规则，是**判例沉积层**——每条 ⚠️ 背后是一次误判。
- **只增不减**：模板 git 统计 +1,657 / −291 行。没有置换机制，体积单调上升是必然。

## 五、维度失衡：19 个 lane 到底在查什么

| 忠实维度 | 问题 | 覆盖 |
|---|---|---|
| 逐字 | 引语在原文里一字不差吗 | **11–12 个 lane**（过度覆盖，且有 93.5% 假红的工具） |
| 对应 | 分析讲的是这一段吗 | 2 个弱覆盖（`check_chinese_layer` / `check_block_keywords`） |
| 可回溯 | 事实/数字断言回得到原文吗 | **0** |
| 不漏 | 关键内容没被略过吗 | **0** |

**铁证**：2026-10-17~19 完工的 10 本书**全部通过 18 lane**（引语逐字 100%、vocab FAIL=0、空段扫描 0 处），而「中文理解」有 45%–94% 整段是英文，`bruja-s-nest` 达 94%。这说明：被检查的部分做到了极致，没被检查的整层坏掉也照样全绿。

## 六、检查型规则会无声失效（假绿清单）

| 工具 | 症状 |
|---|---|
| lane ⑯ `check_xref_chapter` | **全库 100% 跳过**：`load_ref()` 返回零填充字符串 `'01'`，判定用整数 `tgt`，`tgt not in by_chap` 恒真 |
| `check_entities` | 对 108 本非虚构抽 0 段仍 exit 0（「相邻梗概标题丢整节」） |
| `verify_overview_quotes` | 把 194 个文件 / **2,277 行**带标注引语判成「无引语行（正常）」 |
| `check_nav_layer` | 不认中文弯引号 `“”`，整条判定空转 |
| `verify_fragments_indep` | 修前假红 **93.5%**（原文两段相邻但无分隔符，如短信气泡） |
| `check_quote_order` | 会让 **341/483 本**变红 ⇒ 只得退为抽查 |
| `check_chinese_layer` | 进正门后 **150 本存量书变红**（16 本阻断型 ≥50）——这是真实状态，不是误报 |

⇒ 结论：**没有阴性对照自测的检查，等于纸糊的兜底**。这也是后来 `bookform.py` 必须带 `scripts/tests/bookform_negative/` 的原因。

## 七、被证明有效的（保留）

| 规则形态 | 对照实验 |
|---|---|
| 词表由脚本粘贴、人只做减法 | **0 缺陷**；手挑词条 + 手写例句 → **9/16 章有伪造** |
| 写前 grep 预验引语 | 连续 **13 批 0 缺陷**；只读前 30 行动笔 → 3 条凭记忆编造 |
| 总览从「已核实引语池」程序化生成 | **0 缺陷**；凭会话记忆重打 → 概述 5 条 **0 命中** |
| git 三条红线（禁 `add -A`、禁 amend、push 须指令） | 误犯代价不可逆，且已发生 3 次事故 |
| `verify_corpus.py` 语料层验收 | 边界错了，下游所有绿灯都是假的 |

**共同点**：它们替代了一个会出错的动作，而不是事后报警。判据是「它替代了什么动作」，不是「它是不是脚本」。

## 八、被证明空转的（删或降级）

- **劝告型**（「不得跳过」「禁止凭记忆」）：读时点头，写时不产生任何动作。
- **判例型**（事故叙述）：读一次付一次 token，且不改变行为——判例应可 grep，不应顺序读。
- **申报格式型**（「报告须写 lane / 四档」）：格式对了内容可以是空的。
- **数字硬编码**：必然漂移，且漂了没人发现（lane 数漂了 8 天）。

## 九、方案演进

1. 第一轮给了三档：A 保守（−60%）／B 中等（−85%）／C 激进（−95%）。
2. 第二轮收敛为**四层分居**：注入层（`AGENTS.md` ≤8 KB）／按需层（`docs/rules/*`）／判例层（`docs/实测档案/`）／可执行层（`scripts/`）。
3. 第三轮把验收轴换成**忠实四问**（逐字 / 对应 / 可回溯 / 不漏），并引入「先素读原文、后开 md」作为同会话审查的独立性来源。
4. **未采纳**：全库重跑工具基线（一次产出 429 个文件，在多实例共目录仓库里本身就是误提交风险）。
