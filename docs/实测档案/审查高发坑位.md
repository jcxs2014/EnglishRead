# 审查高发坑位清单（第 10 条）

> 2026-09-27 从 `AGENTS.md` 迁出。**规则本身全部留在 AGENTS.md**（那是每本书开工都要读的），
> 迁出的只是**每个规则背后的完整案例叙述**（书名、章号、错在哪、怎么改）。AGENTS.md 现只保留
> 「规则句 + 案例数字 + 指向本档案的指针」。
>
> 触发迁移的直接原因：AGENTS.md 一度 103.9 KB，而 harness 的指令注入预算只有 65,536 字节
> ——**尾部 35% 从未进入任何新会话的上下文**（整张「工具已知盲区速查」表与 git 策略节都在里面）。
> 这是平台硬约束：**没进前 65 KB 的规则，对新会话等于不存在。**

    **四类高发坑位（审查时优先扫描）**：
    - **总览层情节虚构**：主角身份错写、假恋情、假结局、假 POV、假双时间线——概述"做了什么"陈述须 grep 实体（人名/地名）并查该章原文支撑。
    - **人物关系断言**：妻/女/妹等亲属称谓最易凭印象写错且一错贯穿多文件——关系类断言必须**全书 grep 后再落地**（Adam Mine：Magda/Gida 实为三个妹妹，早期误写"女儿/父亲"贯穿 4 文件，靠 ch89 "her shy elder brother" 铁证才修，2026-09-18 实证）。
    - **说话人反转**：同一英文逐字命中但说话人错位——总览层 grep 命中后必 grep 前后 ~200 字符窗口二次确认。Room 实战：8 处金句说话人错位（含 ㉒ Rudbeck→Kim、㉓ Irma→Jonny、㉗ 车主→Astrid）
    - **cliffhanger 跨章场景**：前一章悬念收尾、后一章展开的对话不能整场放进前一章（金句 ㉑ cockfight 实为 ch08 葬礼巴士而非 Animal Action）。**预防**：遇到两章边界的引语必须同时读前后章 text/ 各 ~100 行确认实际发生章节
    - **跨书污染**：从其他书的设定串入（NS 的 Jo/Shayne 实为《A Real Paige Turner》人物；Room in the Ground 的 Schöneberg 实为他书角色）——任何不熟悉的人名/地名都先 `grep -rl "<name>" notes/books/` 排除。
    - **总览引语虚构**：概述/金句集引语即便 verify_quotes 通过也需逐字 grep——经验实证金句层是门禁盲区（NS 金句⑯ 全书查无；Room 金句⑱ "It was a roe deer" 假引语改 verbatim）。
    - **A 类词汇虚构**：词条与例句须出自原文——写入/审查前 `grep -i "word" text/chNN.txt` 验证；分档不许注水（常见词混 ⭐⭐⭐ 高级档视为不合格）。A/B 裁决见 AGENTS.md 第 5 条。
    - **章节标题/文件名系统性偏移**：审计阶段必须全库比对 filename-chapter vs H1-chapter vs text-suffix（book-chapter）三者交叉，发现 >2 个连续偏移即判块状命名坑（Room 实证：19 文件偏高 1，集中在 ch05-13/ch20-28/ch58 三段）
    - **章节编号改动联动 cross-ref**：执行阶段凡改任何章节标题/H1/文件名，必须全库 grep "Chapter N" 引用逐条核对落点（Room 实证：ch13 改"Chapter 12"后 7 处 cross-ref 失效）
