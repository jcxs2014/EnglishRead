# 8.1 第 5 步「修复动作引入新英文」的实例

> 2026-09-27 从 `AGENTS.md` 迁出。**规则本身全部留在 AGENTS.md**（那是每本书开工都要读的），
> 迁出的只是**每个规则背后的完整案例叙述**（书名、章号、错在哪、怎么改）。AGENTS.md 现只保留
> 「规则句 + 案例数字 + 指向本档案的指针」。
>
> 触发迁移的直接原因：AGENTS.md 一度 103.9 KB，而 harness 的指令注入预算只有 65,536 字节
> ——**尾部 35% 从未进入任何新会话的上下文**（整张「工具已知盲区速查」表与 git 策略节都在里面）。
> 这是平台硬约束：**没进前 65 KB 的规则，对新会话等于不存在。**

   5. **修复动作引入的新英文同样要过门禁——"已修"不等于"已对"**（2026-09-27 新增）

      审查方 d 步"修缺陷"时**照抄子代理报告里的英文写进分析层、未回原文核**，**自己新造 6 处伪造引语**
      （Jane Eyre：`He is more myself than I am` / `You have no soul, pet` /
      `Mr. Eyre of Funchal, Madeira` / `Consider that eye…resolute course` /
      `besides ourselves` / `to talk to, and with, a husband`），由 `sweep_analysis_inline` 抓出。
      **根因**：禁令 1 只约束"写作时"，而**修复时引入的文本同样不是从 `text/` 复制的**。
      → **修复每一处后，对该处新写入的全部英文跑一次 sweep / flat 核验**；
      替换文本**写入前必须先 flat 比对**（AGENTS 8.2 禁令 3 的附加实例：改 A 时极易再造 B）。

   6. **接着写下一章前，先读上一章的 H2 集合 / 子项集合 / 引语标记，照它写**
