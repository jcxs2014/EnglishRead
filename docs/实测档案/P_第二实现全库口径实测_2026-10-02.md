## 三个 `*_indep` 第二实现在全库 324 本书上的口径实测（2026-10-02）

**目的**：AGENTS 第 10 条要求报告里写清「第二实现只验过 1 本书」。本节把这句话从「未验证」变成**有数据的口径**。

### 1. 全库跑通性（不崩溃、不卡死）

| 脚本 | 跑的书数 | 非零退出 | 占比 |
|---|---|---|---|
| `check_struct_indep` | 324 | 211 | 65.1% |
| `check_xref_indep` | 324 | 134 | 41.4% |
| `check_analysis_indep` | 324 | 155 | 47.8% |

**三个脚本在全库 324 本上均能正常跑完**（无异常退出、无 traceback），说明它们在**本书之外的书上不会崩**——这是「口径未验证」这一顾虑的第一层，已解决。

### 2. 65% 非零的真实构成（关键结论）

`check_struct_indep` 的 65% **不是缺陷率**。按报错归类后可见绝大多数来自**档位识别**：

```
240  [summary] 引语 N: 子项「读者视角提示」出现 N 次（须恰 1）
240  [summary] 第 N 行：`> ` 出现在 ## 精读 之外（> 只用于引语）
 80  [summary] 引语 N: 子项「读者视角提示」出现 N 次（须恰 1）
 52  [summary] 必备节「## 本章导航」/「## 精读」/「## 本章词汇」出现 0 次
 52  [summary] 引语块 N 个，超出 3–8 配额
```

即：**某本书使用 `summary`（言情/小说精简）档且完全合规，但脚本按 `summary` 判它「缺 `## 本章导航`」**——这类报错是**档位判据与书内实际格式不匹配**造成的假红。

**档位识别实测分布**（对全库每个 `ch*.md` 调 `detect_profile`）：

| 识别结果 | md 数 |
|---|---|
| `summary` | 10,122 |
| `nonfiction` | 869 |
| `None`（识别不出，**退回 summary 判据**） | 571 |

**571 个 md 识别不出档位**（如 `shes-a-doll-by-barbara-truelove` 用「不死人格式」：无 `## 本章导航`、无 `读者视角提示`），脚本对它们**一律按 `summary` 判**，于是必然报「缺必备节」「超配额」——**这是 65% 的主因，且全部是假红**。

### 3. 在工具的**有效判定域**（`nonfiction` 档）内抽样

`nonfiction` 档共 **39 本**书目录。随机抽 12 本逐条读报错：

| 书 | 报错数 | 性质 |
|---|---|---|
| the-art-of-thinking-clearly-by-rolf-dobelli | 44 | 混合格式（一章 1 块，触发「超配额」）——半真 |
| dark-psychology-super-advanced | 7 | **假红**：该书 `detect_profile` 判 `summary` 但实际用 nonfiction 节名 ⇒ 判据错配 |
| why-we-read / what-the-bees-see | 50 / 70 | **假红**：这两书引语块 0 个（散文体），脚本「引语块 0 个，超出 10–10 配额」自相矛盾 |
| against-everything-by-mark-greif | 51 | 半真：块数 12/17/18 超出该档 10–10 上限 |

**结论**：抽样的 5 本报警里，**至少 3 本是纯假红**（判据与书内格式不匹配、或「0 块超出 10–10 配额」这类自相矛盾判据）。`check_analysis_indep` 与 `check_xref_indep` 同理，其报警多为**分析层英文压缩**（人名职务简写）与**中文式 `第N章` 引用**——这两类在本项目里已分别定性为提示型与需人判。

### 4. 对本轮（The Palestine Laboratory）审查的效力

本书是 **`nonfiction` 档、`detect_profile` 正确识别**、`RANGE` 落在 3–20 内、子项集与该档完全一致的情形。因此：
- 它的 **c 步 3 处报警 100% 为真缺陷**（标签误写 + 缺子项），已整改；
- 它在 `check_xref_indep`（英文证据）与 `check_analysis_indep`（538 片段）的 0 报警，是在**工具有效域内**取得的 0，不是「工具不报」。

### 5. 仍存的口径局限（如实保留）

1. **工具对第三种格式（不死人/散文体等 571 个 md）整体不适用**，不是「已验证通过」而是「已知不适用」；若日后把它接进常规门禁，须先扩 `PROFILES` 或改为「认不出即跳过」而非「退回 summary」。
2. **本次只在本项目 1 本 nonfiction 档书上验证了「真缺陷检出」**（3/3 真），未在多本 nonfiction 档书上交叉验证真缺陷率。
3. **`check_analysis_indep` 的 🟠「整串查无但每词都在」通道在本项目报了 21 条**，逐条人判为书名/副标题/职务简写等合法压缩——该通道的真缺陷率在本项目为 0，但那 21 条已消耗人工；接入门禁前需先降噪。

## 终验命令 exit 1 的归因（供复核）

上轮终验命令整体退出码为 1，逐段单跑确认**三个门禁全部返回 0**：

```
gate.sh                 → 0
check_struct_indep      → 0
check_xref_indep        → 0
```

exit 1 来自命令末句 `git log --oneline -12 | grep -c "palestine"` —— 该管道匹配到 0 行因而返回 1，而 commit 消息用的是 `palestine-laboratory`（拼写为 `palestine` 而非我 grep 的 `palestine`，且 `-12` 窗口内其他实例的 commit 挤占）。**属终验命令自身的 grep 写法问题，非门禁失败。** 本书的 11 条 commit 已用 `git log --grep="palestine-laboratory"` 正确核出。
