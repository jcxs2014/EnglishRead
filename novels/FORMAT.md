# 小说精读格式规范

> 本规范**仅适用于 `novels/` 目录**；`economist/` 与各源文章精读仍遵循根 `AGENTS.md` 定稿的"逐句精读"格式（每原句一个分析块）。两者**不要混用**。
> 原因：小说以叙事连贯性为核心，逐句打散会撕裂文脉；且体量通常为文章 100–500 倍，逐句在人力上不可行。改以**章为单位推进**。

---

## 一、目录组织

```
novels/
├── INDEX.md                              ← 小说库总索引（章节完成度、状态）
├── FORMAT.md                             ← 本文件
└── <slug>/                               ← 每本小说一个文件夹（slug = 书名转 snake_case）
    ├── library/
    │   └── <slug>.epub                   ← 原始 epub（不入 git）
    ├── 精读/
    │   ├── <slug>_导览.md                ← 全书导览（人物/主题/背景，可选，首次读到中段时回填）
    │   └── CH01_章节标题.md              ← 逐章精读（主体，每章一个文件，进 git）
    │   └── CH02_章节标题.md
    │   └── ...
    ├── 词典.md                            ← 全书包词汇/表达（累积，按章追加）
    ├── 人物.md                            ← 人物档案与关系（累积，按章追加）
    ├── 主题.md                            ← 主题与母题（累积，按章追加）
    └── 总结.md                            ← 终章后写的全书总结（主题脉络、写作技法、个人感受）
```

**要点**：
- `library/` 整目录 gitignore；原 epub 是参考材料，不进库、不上网。
- `词典.md / 人物.md / 主题.md` 都是**追加模式**（append-only），不要为了修一句重写整个文件；修正文案用 `patch`。
- `精读/CH*.md` 每章一个文件，进 git；文件名 `CH` + 两位序号 + `_` + 章名（英文原名的简短 slug，保留原文语言）。
- 章节顺序用编号强制锁定，避免 epub 目录与精读文件脱节。

## 二、逐章精读文件格式（`精读/CH01_章节名.md`）

### 2.1 frontmatter

```yaml
---
状态: 未读
书: <slug>
章节: 1
章题: <原文章题>
完读日期: <YYYY-MM-DD，初读；完成精读时更新或加一行完成日期>
---
```

`状态` 三态：`未读` / `精读中` / `已精读`（与文章精读一致，便于 Obsidian `status` 搜索）。

### 2.2 文件章节结构（顺序不得打乱）

0. frontmatter
1. `# CH01 <原文章题>`
2. `## 章速览`
   - 一段中文概述（150–250 字），交代本章**发生了什么、谁推谁、情节走向**，作为整章记忆锚点。
3. `## 关键段落精读`
   - 本章挑 3–8 段精读（**不是每段都精读**，挑有代表性的：开篇气氛、关键对白、转折点、结尾收束、意象密集处、语言出彩处）。
   - 每段一个 `### 段落 K：<一句概括>` 小节，含四子项：
     - **原文**：引用本段原文（英文，可 200–500 词）。
     - **中文理解**：一段自然中文概述（不是逐句翻译，是"讲清楚这段在说什么"）。
     - **叙事功能**：这段话在推动什么——人物塑造 / 世界观铺陈 / 情节转折 / 悬念埋设 / 主题铺垫 / 氛围营造。
     - **语言亮点**：修辞、节奏、视角切换、反讽、留白等具体的语言层面。
4. `## 人物与关系`
   - 本章涉及的人物（首次出场用 `**姓名**（角色说明）`）；关系变化用 `→` 箭头串起，如 `A 怀疑 B → A 得知真相 → A 与 B 决裂`。
5. `## 主题与母题`
   - 本章体现或推进的主题线索（2–5 条），与书的主题列表对照（主题.md 中登记的主题名），让读者能看到"这条线在这里被推进一步"。
6. `## 语言与风格`
   - 聚焦语言本身的观察（1–3 条）：比喻质量、长句节奏、口语与书面语的张力、视角的可靠性、叙事时间的跳切等。
7. `## 关键表达`
   - 3–5 个值得记的短语 / 句式 / 词汇，每个附：`英文原句` / `中文释义` / `为何值得记`（可迁移到什么场景）。
8. `## 章末速记`
   - 3 条要点，作为"如果只记得三件事"的浓缩。

## 三、配套累积文件格式

### 3.1 `词典.md`

按章累积，每章一节：

```markdown
# <书名> · 词典

## CH01 · <章题>

### ⭐⭐⭐ 高级
| 词/短语 | 中文释义 | 原句（简） | 备注 |
|---|---|---|---|
| ... | ... | ... | ... |

### ⭐⭐ 进阶
...

### ⭐ 基础
...
```

三档标准同文章精读：**高级**=文学/抽象/少见的用词与隐喻；**进阶**=通用但精准的动词/形容词、固定搭配；**基础**=高频但搭配特殊的表达。

**追加模式**：每章写完精读后在文件末尾加新节，不改旧节。同词重复出现——只记**首次出现**那一章；后续再碰到可忽略或加一句"CH05 再次出现，含义略有偏转"。

### 3.2 `人物.md`

```markdown
# <书名> · 人物档案

## 已登场人物（按首次出场排序）

### **姓名**（首次出场：CH01）
- 身份：...
- 外貌/气质关键词：...
- 与主线关系：...
- 关系网（更新记录）：
  - CH01：与 A 相识
  - CH03：与 A 反目；结识 B
- 关键对白或独白（引 1–2 句）：...
- 可能的弧光方向（读的过程中随时更新）：...
```

### 3.3 `主题.md`

```markdown
# <书名> · 主题与母题

## 已识别主题
1. 主题 A —— <一句话定义>（首次显性于 CH01）
2. 主题 B —— ...

## 主题推进脉络（按章）
- CH01：主题 A 出场（通过 ... 铺垫）
- CH02：主题 A 深化；主题 B 初现

## 母题与意象清单
- <意象>（首次出现 CH01；再现 CH03/CH07；含义演变：...）
```

### 3.4 `总结.md`（全书读完后写一次）

包含子节：
1. `## 一句话书评`：三句话内说清楚这本书写什么、好在哪里。
2. `## 主题脉络回顾`：各主题如何在全文中起承转合。
3. `## 人物弧光`：主角/关键配角如何变化。
4. `## 写作技法亮点`：叙事视角、结构、语言、节奏、留白——挑 3–5 项最突出的。
5. `## 个人感受与争议`：喜欢 / 不喜欢 / 争议性选择（诚实，不写套话）。
6. `## 推荐语`：写给未来的自己或朋友，什么情境下值得读。

## 四、推进节奏与交互

- 用户说"**精读第 N 章**"或"**CH0N**"→ 打开 epub 对应章节，按上述格式精读并写盘。
- 用户说"**继续**"→ 读下一章。
- 用户说"**跳过**"→ 只更新 INDEX 状态，不写精读文件。
- 用户说"**只看第 N 章**"→ 只输出中文概述 + 关键段落，不写盘（除非用户再说"写盘"）。
- **词汇分级**不独立成一次会话任务——按章精读时顺便补进 `词典.md`。
- 中途可随时 `人物.md / 主题.md` 追加条目；不需要等全书读完。

## 五、与文章精读格式的差异对照

| 维度 | 文章精读（AGENTS.md） | 小说精读（本文件） |
|---|---|---|
| 推进单元 | 原句 | 章 |
| 精读范围 | 每句必精读 | 每章 3–8 段选择性精读 |
| 分析颗粒 | 句法/词法/长难句 | 叙事功能/人物关系/主题脉络 |
| 词汇 | 文章末词汇分级 | 全书包词典（按章追加） |
| 跨单元追踪 | 无（单篇文章） | 人物.md / 主题.md 跨章追踪 |
| 全书收尾 | 精读结束总结 | 总结.md（人物弧光+主题脉络+技法+个人感受） |

## 六、git 与同步

- `library/*.epub`：不入 git、不上网站（.gitignore 已配 `novels/**/library/`）。
- 其他文件（精读/词典/人物/主题/总结/INDEX）进 git，按章节完成即 commit、不 push，整书定稿后询问再 push。
- 同书不同机器读到不同进度——**不要并行写同一章文件**；以 INDEX.md 的"精读状态"列为同步信号。
